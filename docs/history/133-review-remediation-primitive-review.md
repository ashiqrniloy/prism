## Reproducible contract cases (assign regressions, not tests added here)

1. **Task 2, owner leak — confirmed SQLite, source-equivalent PostgreSQL.** In a fresh SQLite `:memory:` store, `appendSession({id:"s",tenantId:"a",accountId:"x",userId:"u",createdAt:iso,updatedAt:iso})`, append entries under `s`, then `queryEntries({sessionId:"s",tenantId:"b",limit:2})` and same query with `leafId` each return **2 rows** today. Expected empty page and no cursor for tenant/account/user or mixed mismatch, matching-owner pages intact; unscoped admin read unchanged. Probe foreign session ID, same-session foreign leaf, SQL-injection-shaped bound identifiers. `get/list/readBranchPath` are separate unscoped `SessionStore` seams; do not present them as owner-checked query APIs. Threat: a caller able to supply a guessed session/leaf ID plus a foreign scope gets transcript bodies despite scope; never post-filter returned rows.
2. **Task 3, checkpoint replay — confirmed.** Inject one save failure on third save (after a function node effect; first two saves are initial and running), use `retries:1`. Current `runWorkflow` reports `succeeded`, effect invoked **twice**, saves 5. Expected first failure propagated and effect count 1. Add transient *execution* error control (two calls then success), loop iteration save and suspend save failures, superstep wave save; avoid asserting exactly-once recovery after a crash with unknown external outcome. Existing `run.test.ts:290-321,1194-1214` covers different boundaries, not this retry case.
3. **Task 4, branch filters/cursors — confirmed.** Seed chain of 3+ entries with mixed kinds/runs and identical timestamps. `queryEntries({sessionId:"s",leafId:last,kind:"label",order:"desc",limit:2})` currently returns first two **root-first**, including non-label, and has no `nextCursor`; other filters and cursor likewise ignored. Require SQL-filtered/tie-stable asc/desc pages with no skips, invalid cursor fail closed, foreign leaf/session zero rows, ownership from Task 2. Keep `readBranchPath` root→leaf semantics independent of query ordering.
4. **Task 5, mutable ingest — confirmed from `add()` and output-copy-only tests.** Mutate nested `entry.message.content[0].text` after `createMemorySessionStore([entry])` or `await store.append(entry)`. Subsequent `get/list/readBranchPath/searchSessions` reflect caller mutation today; expected original value. Check both constructors and append.
5. **Task 6, activity rewind — confirmed SQLite, source-equivalent PostgreSQL.** Write a session with a newer `updatedAt`, then `appendRun` with older `startedAt` (also usage/event variants). `querySessions({id:"s"})` reports older `updatedAt`; expected max activity timestamp. Test equivalent instants with differing timezone/precision and concurrent writes before choosing DB comparison; preserve `appendSession` explicit metadata/CAS semantics and ownership.
6. **Task 7, unbounded branch rows — confirmed by SQL shape.** 300-entry linear branch, `readBranchPath({sessionId:"s",leafId:"e299",limit:2})` returns 2 with cursor `"2"`, but the SQL SELECT returns/materializes all 300 before JS slicing. Test page N, equal timestamps, missing leaf, malformed/huge offsets and instrument SQL returned rows ≤ `limit+1`; recursive traversal can still walk full ancestry per page.
7. **Task 8, measurement-first.** Delayed fake store, 8 distinct scopes, 10 ms per vector/lexical leg: compare ordered hits, citations, audit, active-call peak and elapsed time to serial below; test rejected leg, abort, grant revoked between query and assembly. This is a *latency opportunity*, not an authorization defect. Preserve empty-scopes fast path and the existing hard cap.
8. **Task 9, duplication review.** Search already shares resolution/kind/snippet/row codecs. Only consolidate demonstrably identical remaining validation/cursor semantics if total diff shrinks; dialect-local FTS ranking, SQL CTEs and placeholder indexes stay separate. Regression: equivalent owner/kind/time/cursor/tie results in both adapters after Tasks 2–7.

## Baseline and rerun

Index shapes in `src/testing/persistence-schema.ts:674-704` include `(session_id,timestamp,id)` and `(session_id,id)`; ancestor traversal still grows with depth. SQLite owner probe returned 2 ordinary + 2 leaf rows under foreign tenant. After an older run, `updatedAt` moved backward to its 2025 timestamp.

Reproduce SQL probe with `bun -e` from repo root (no service or new dependency):

```ts
import { Database } from "bun:sqlite";
import { createSqlitePersistence } from "./packages/prism-core/src/sessions/sqlite/persistence.ts";
const db = new Database(":memory:");
const store = createSqlitePersistence({ filename: ":memory:", database: db });
const iso = "2026-01-01T00:00:00.000Z";
await store.appendSession!({ id: "s", tenantId: "a", accountId: "x", userId: "u", createdAt: iso, updatedAt: iso });
for (let i = 0; i < 300; i++) await store.append({
  id: `e${i}`, sessionId: "s", parentId: i ? `e${i-1}` : undefined,
  kind: i % 2 ? "message" : "label", timestamp: iso, label: `label-${i}`,
});
console.log((await store.queryEntries({ sessionId: "s", tenantId: "b", limit: 2 })).items.length); // 2: expected 0
console.log((await store.queryEntries({ sessionId: "s", tenantId: "b", leafId: "e299", limit: 2 })).items.length); // 2: expected 0
console.log(await store.queryEntries({ sessionId: "s", leafId: "e299", kind: "label", order: "desc", limit: 2 })); // e0,e1; no cursor
console.log(await store.readBranchPath({ sessionId: "s", leafId: "e299", limit: 2 })); // 2 rows, cursor "2"; SQL fetched 300
store.appendRun({ id: "r", sessionId: "s", status: "running", startedAt: "2025-01-01T00:00:00.000Z" });
console.log((await store.querySessions({ id: "s" })).items[0]?.updatedAt); // 2025-01-01T00:00:00.000Z
store.close();
```
