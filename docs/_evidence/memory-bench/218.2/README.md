# Plan 218.2 evidence

Plan 218.2 hardens the memory system's session tiers for small worker models. Each product change is decided on the
worker replay screen (`scripts/memory-bench/worker-replay/`, see `scripts/memory-bench/README.md`) before any
agent-level paid run. Evidence holds ids, counts, rates and hashes; no transcript, record, scope or chunk text.

| File | What it is |
|---|---|
| `gates/owner-gate-replay.json` | The replay gate record: the worker models (OpenCode Go), the output limit, the per-model input-token ceiling, the fixture hash, the frozen criteria hash, and the decision rules of Tasks 2, 4, 5 and 6 with their hash (`REPLAY_RULES`). The live replay refuses to run until the owner approves it, and refuses a rule changed after the baseline. |
| `replay-baseline.json` | Task 1: the current product replayed through each model, with its product hash and the rules hash it ran under. Written before Task 2 lands. |
| `replay-task2.json` | Task 2: the 60 STM requests alone (`--only stm --label task2`) on the product with `record_event`'s `status`, `corrects`, `durable` and `resolves`, same models, fixture hash, rules and ceiling (gate record `changes`, 2026-11-14). Decides Task 2's rule: the English patterns are kept as a union for records without the fields. |
| `replay-task4.json` | Task 4: the 60 STM requests alone (`--only stm --label task4`) on the product with the automatic evidence chunk at `stm.autoChunkBytes: 1024`, same models, fixture hash, rules and ceiling (gate record `changes`, 2026-11-14). Decides Task 4's rule: coverage rose on all three models, but Muse's chunk bytes per 10k source tokens (188) passed twice its baseline (74), so the rule asked for off; the owner turned it on by default (2026-11-15, gate record `changes`). |
| `replay-task5-incumbent.json` | Task 5: the 48 WM requests alone (`--only wm --label task5-incumbent`) with the four per-record tools (`keep`, `summarize`, `derive`, `discard`) on the product after Task 4, the incumbent Task 5's rule reads. Same models, fixture hash, rules and ceiling (gate record `changes`, 2026-11-15). |
| `replay-task5-judge.json` | Task 5: the same 48 WM requests (`--label task5-judge`) with protected records settled first and one `judge` call over ordinals. The rule said judge loses on one check (DeepSeek kept 89 of 96 later-step records against the incumbent's 90); the owner shipped judge (2026-11-15, gate record `changes`). The runs' `--wm-format` and `--settle-first` flags were removed with the losing format. |
| `replay-task6.json` | Task 6: the 24 long-scope WM requests alone (`--only wm --set long-scope --label task6`) with a scope digest (one digest call per scope hash and model, `minBytes` 8,192, `maxBytes` 2,048) in place of the full scope in the WM request. `decideTask6` against `replay-task5-judge.json`: `defaultOn: false` (later-step records kept of 48: Muse 42 → 43, DeepSeek 44 → 43, MiMo 34 → 31), so the digest code and the run's `--scope-digest` flag were deleted. The run resumed the first attempt's checkpoints by `--state-key` after kernel edits moved the product fingerprint (`stateKey` in the report); 66 of 72 rows ran under the earlier fingerprint, and no memory-package file changed between them. |
| `long-horizon-manifest.json` | Removed by plan 218.3 Task 12 (2026-11-19) with the long-horizon family, as plan 218.1 Task 5 planned: Session-Bench replaced it. It held Task 8's precondition reading (14 WM passes with an item per dev session at the defaults) and the estimate (about 151M input tokens per model for two dev sessions and five arms). Git history keeps the file. |
| `m1-whole-run-trace.json` | Task 8: why gate M-1's large-model long-session cell read 13.6M (STM), 6.9M (OM-before) and 1.8M (memory-off) input tokens. Re-runs were counted: each job's `inputTokens` sums every process run in its attempt's wire log. That is 5 runs for STM (4 checkpoint protocols), 3 for OM-before and 3 for memory-off. The reported rows' family meter reads 3.49M, 5.54M and 1.50M. Counts only. |
| `replay-after.json` | Task 9: the whole fixture on the same models, fixture hash and rules on the product after Tasks 2–7 (`--label after`; product `c1c741b2…`), with `paired`: `pairReplays` against `replay-baseline.json`, both product hashes and `{ before, after, delta }` per model for the STM and WM rows and usage (written by `--pair`, because the run started before the pairing code landed). 0 failed requests, 3.94M input tokens over the three models (about $0.26). |
| `decisions.md` | Task 9: for each rule of Tasks 2, 4, 5 and 6, the counts, the outcome, the owner's overrides and what was deleted; then the after-replay against the baseline and its reading. |
| `equivalence.json` | Task 9: `prefix-probe.mjs --equivalence` against a worktree at HEAD `0d11738e` (the tree without plan 218.2's uncommitted changes): the LTM answer-path requests are `identical`, `rerunArms` empty. |
