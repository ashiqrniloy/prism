# Phase 11 Part O.4 — memory retention: use-based verification, two-strength retention, capacity, and scope widening

## Objectives

- Keep long-term memory from becoming a graveyard while never losing what matters. Defects addressed:
  - **D6: two contradictory lifecycles.**
    - Fabric verified notes are never archived, because `archiveStale` only touches candidates (`fabric/src/promote.ts`).
    - The scoped layer proposes archiving a verified note when `uses·e^(−age/30) < 1` (`scoped/lifecycle.ts` `decayScore`). One use means archive the next day; two uses, after about 21 days.
    - Use counts live in two places: note metadata and `ledger.json`.
  - **D7: calendar-time decay.** A month away archives everything.
  - **D8: exponential decay multiplied into relevance** (`scoped/read-policy.ts` `scoreScopedHit`). A stable 90-day-old fact keeps 5% of its score.
  - **D14: importance is a neutral 0.5 with no source.**
  - **D15: lifecycle work pages the whole store** (`exportedRecords`).
- **Two strengths per note** (Bjork & Bjork's New Theory of Disuse, 1992):
  - **Storage strength S** only accumulates evidence of value:
    `S = a·explicit + b·log(1+distinct_sessions_used) + c·helpful − d·harmful + e·outcome_tagged`
  - **Retrieval strength R** is ACT-R base-level activation over *use* events (Anderson & Schooler 1991):
    `R = ln Σⱼ tⱼ^(−d)`
    - `t` counts **sessions in the note's scope** since use `j`.
    - `d` depends on kind (episode 0.8, fact 0.4, procedure 0.4, preference 0.2; provisional until plan 188.6).
- Verify notes by use across separate sessions. Count helpful and harmful evidence. A correction reopens a note for reconsolidation.
- **Retention:**
  - Supersession or expiry is the only path that sets `validTo`.
  - **Archive** requires all of: low R, low S, past the grace period, not pinned, not on legal hold. A high-S note is never archived by decay alone.
  - **Capacity budget per scope:** merge first (near-duplicates; episodes into a general "history of X" note), then archive the lowest S·R.
  - The archive stays searchable. Using an archived note revives it.
- **Scope widening and narrowing** (the rules of plan 188.2):
  - project → agent when a lesson is verified in ≥ 2 unrelated projects with no contradiction
  - path → project when it holds in ≥ 2 sibling subtrees
  - a wider note contradicted in k projects is superseded
- One maintenance pass per scope, `fabric.maintain()` / `memory:maintain`, suitable for a nightly run through the headless scheduler.

**Evidence** (owner-approved memory-lifecycle analysis, 2026-10-19):

- **Forgetting follows a power law, not an exponential** (Wixted & Ebbesen 1991). The environment's need for information has the same shape (Anderson & Schooler 1991), which is the basis of ACT-R base-level learning.
- **Storage strength and retrieval strength are separate** (Bjork & Bjork 1992). Forgetting is a loss of access, not of the stored trace, so archived memory should come back on use.
- **Spacing** (Cepeda et al. 2006). Verify on distinct sessions.
- **Retrieval-induced forgetting** (Anderson, Bjork & Bjork 1994). Reinforcing whatever is retrieved suppresses competitors, so credit use, not retrieval.
- **Reconsolidation** (Nader 2000; REALM, arXiv 2609.16053, abstract only). Retrieval makes a note changeable.
- **Selective deletion improves agents** (Xiong et al. 2025, arXiv 2505.16067). Later task outcomes are free quality labels.
- **ACE** (arXiv 2510.04618). Helpful and harmful counters with incremental updates.
- **Schema formation** (Tse et al. 2007). Repeated episodes merge into general knowledge.
- **Generalisation across contexts** (Sun et al. 2023). Widening by replication.
- **Proactive interference** (Wang & Sun 2025). Superseded values must leave the active index.
- **Bounded, budget-aware forgetting** (SSGM, arXiv 2603.11768).
- **Hygiene metrics.** DreamBench-SWE (arXiv 2608.20664) reports a stale-use rate of 0.20 and a repeated-error rate of 0.57. Plan 188.6 measures these.

## Expected Outcome

- One lifecycle module, `fabric/src/lifecycle/`, owns status, use events, S, R, verification, archive, revival, capacity, merge, and widening. The scoped layer reads it.
- The scoped ledger's `uses`/`status`/`lastUsedAt` rows, `runScopedPromotionPass`, `runScopedGcPass`'s decay, `scoreScopedHit`, `isStaleCandidate`, and `promote.{verifyAfterUses,archiveAfterDays}` are deleted. The ledger keeps only what is not lifecycle (pending approvals, stats).
- Note metadata (frontmatter `prism.lifecycle`):
  ```yaml
  prism:
    lifecycle:
      retrievals: 14
      uses: [{ s: 41, at: ... }, ...]   # last 32 use events: scope-session ordinal + time
      use_sessions: 6
      helpful: 3
      harmful: 0
      contradicted_in: []
      storage: 1.9
      pinned: false
  ```
- **The scope clock.** A per-scope session ordinal, incremented once per session that opens with the scope active. It is stored as control state: `.state.json` (markdown) or the store method Task 2 adds.
- Config `lifecycle`:
  ```ts
  lifecycle: {
    verifyAfterSessions: 2,
    decay: { episode: 0.8, fact: 0.4, procedure: 0.4, preference: 0.2 },
    storageWeights: { explicit: 1, sessions: 0.5, helpful: 0.5, harmful: 1, outcome: 0.5 },
    archive: { retrievalBelow: -2.0, storageBelow: 1.0, graceSessions: 10 },
    capacity: { user: { notes: 200, tokens: 20000 }, agent: { notes: 200, tokens: 20000 }, project: { notes: 500, tokens: 60000 } },
    merge: { duplicateDice: 0.8, episodes: { minCluster: 5, model?: "provider/model" } | false },
    widen: { minProjects: 2, minSiblings: 2, contradictionsToSupersede: 2 },
  }
  ```
  Every number is provisional until plan 188.6 and is documented with its meaning.
- **Recall ranking.** `score' = fused + w_R·σ(R) + w_S·σ(S)`, a bounded additive prior (default weights 0.05 each). Validity and status filters apply first.
- **Archive search.** `memory.recall { includeArchived: true }`. When active results are weak (top coverage < 0.34, plan 188.1 Task 3), archived hits are appended automatically, marked `[archived]`, after active hits. Citing an archived note revives it.
- `fabric.maintain({ scope?, signal })`, the `memory:maintain` command, and a documented nightly recipe on `@arnilo/prism-headless`'s scheduler.

      only this thread's text is measurable — a host that writes notes into many threads should expect
      merges and evictions to be conservative.
    - **Duplicate merge** (`lifecycle/merge.ts#duplicateGroups` + `mergedMetadata`): pass 1 groups by
      `kind|level|globs|key`, pass 2 folds same-kind same-glob notes at term-set Dice ≥
      `duplicateDice` (0.8, bounded to [0.5,1]) when neither carries a `key`. The survivor is the note
      with the higher S, ties broken by id ascending; pinned notes and episodes are never inputs (the
      loser is archived, and an episode's merge is the episode pass). The survivor keeps its own text,
      key, kind, level, and status, and absorbs keywords, tags, links, evidence ids, the highest
      promotion stamp, and every counter (`useSessions`, `retrievals`, `helpful`, `harmful`,
      `lastSession`, and the use log re-sorted and capped at 32).
    - **Write path deviation, on purpose.** Duplicate merging writes through the lifecycle
      (`mergeMetadata`) rather than `remember`: the survivor's text is unchanged, so the text-level
      trust scan has nothing new to scan, and re-writing it through `remember` would re-embed, re-run
      consolidation, and could move the note's status. Episode merging does go through `remember`
      (candidate + `generated.by: promotion`), so consolidation, provenance, redaction, and the trust
      scan all apply, and `summarizeEpisodeCluster` additionally applies `scanScopedMemoryContent` and
      the redactor to the model's answer before anything is written.
    - **Episode merge** (`lifecycle/merge.ts`): clusters are `minCluster` (default 5, set true by
      `lifecycle.merge.episodes` being present — `false` and absence are the same off state) or more
      active episodes of one scope sharing a `key`, else the first tag (subject `#tag`). One model call
      per cluster, `maxTurns: 1`, `maxToolCalls: 1`, the worker limits (message bytes) and the
      `EPISODE_MERGE_SYSTEM` prompt live here rather than in `consolidation/prompts.ts` so the module
      owns its own contract. Fail-closed at every step: a missing client, a failed call, a malformed
      answer, a trust-scan hit, or a redactor hit skips the cluster and archives nothing. A `key`
      subject becomes the summary's `key`; a tag subject does not.
    - **Eviction** (`lifecycle/capacity.ts#evictionOrder`): ascending `S·exp(R)`, ties by id. Skipped:
      pinned notes, notes with `S ≥ archive.storageBelow`, and notes without readable text. The
      archive verb is `evicted`.

## Compromises Made

- **Calendar retrofits were removed, not migrated.** `promote.archiveAfterDays`, `scoped.decay.candidateArchiveDays`,
  `scoped.policy.decay.tauDays`, and the `.memory/state.json` per-note lifecycle rows are gone rather than mapped onto the new
  model. A host that relied on day-based archiving now gets rule-based archiving plus one warning about ignored ledger fields.
  Rationale: a date cannot be converted into a session ordinal without inventing history. Cost: two config breaking changes,
  both in the CHANGELOG and the README config block.
- **`useSessions` is not derived from the use log.** The log is capped at 32 events, so a note cited for years keeps a count
  that outruns its log; retrieval falls back to Petrov's even-spacing approximation over the covered interval. Rationale:
  bounded metadata. Cost: an old, heavily used note's R is an approximation, not an exact sum.
- **Text is the boundary of capacity enforcement.** `memory.get` is thread-scoped and capped at 1000 ids while the scan is
  resource-scoped and metadata-only, so notes written by another thread count toward a budget but cannot be merged or evicted
  by this instance. Rationale: no new cross-thread read API inside this plan. Cost: a scope can stay over budget; the report's
  `overBudget` entry and the status warning say so instead of lying.
- **The nightly recipe is host code.** `@arnilo/prism-headless` has no target that runs a package command without a model turn,
  so `memory:maintain` is documented as a host call (`agent.commands.run`) rather than a scheduler target. Rationale: the
  fabric's job is the pass, not the clock. Cost: the host writes five lines.
- **The lifecycle example installs no provider.** See Task 7 notes: no path it demonstrates reaches a model, so a mocked
  provider would have proved nothing. Cost: the example does not exercise `mockProvider`; the gate still runs it offline.

## Follow-up completed (2026-10-19): `memory:lifecycle`

- **What landed.** New `src/lifecycle/inspect.ts`: `inspectNote({ id, metadata, status, clock, archive?, decay?, storageWeights? })`
  returns `LifecycleNoteView` — kind, note scope, key, status, `created`, `pinned`, the use log, `useSessions`/`retrievals`/
  `helpful`/`harmful`, `storage` (S), `retrieval` (R), `importance`, `archive: { eligible, reasons }`,
  `widen: { eligible, reasons }`, plus `archivedAt`/`archivedFrom`/`widenedTo`/`mergedInto`/`validTo`/`contradictedIn` when set.
  `describeNote(view)` prints the one-line form an operator reads.
- **Cannot drift from the rules.** `archive.eligible` is `shouldArchive(...)` itself, and the refuse codes are computed in that
  predicate's own order (`pinned`, `retrieval`, `storage`, `grace`), so a view never claims a note is archivable when the pass
  would not archive it. S and R come from `storageStrength`/`retrievalStrength`; `importance` is `noteImportance(S)`.
- **Widening verdict is note-level by design.** `widen.reasons` names the per-note gates (`unverified`, `kind`, `harmful`,
  `contradicted`, `pinned`); replication across projects needs every project resource, so that stays `maintain()`'s decision and
  the output says `widen=note-eligible` rather than pretending to know. Documented in the README so the field is not read as a
  promise.
- **Command.** `memory:lifecycle` (`createMemoryLifecycleCommand` in `index.ts`) scans the bound scopes with `store.scanMetadata`,
  reads each scope's own session clock from `scopeCounter` (falling back to the session clock), sorts most-retrievable first, and
  takes `{ id?, key?, includeArchived? (default false), limit? (default 20, max 100) }`. Output is `{ ok, total, notes, text }`
  with `total` the pre-limit count. A store without `scanMetadata` fails closed with `reason: "no_scan"`. Held notes stay
  invisible because the store's scan already excludes them.
- **Tests.** `src/lifecycle/__tests__/inspect.test.ts` (S/R/use-log values, every archive refuse code including the high-S note and
  the grace boundary, every widening code, the printed line) and `src/__tests__/lifecycle-command.test.ts` (package command over a
  seeded SQLite index: default view hides the archived note, `includeArchived` shows it with `archivedAt`/`archivedFrom`, `id` and
  `key` filters, `limit` caps rows but not `total`, and the header line). A fixture whose use events lacked `at` was silently
  unparsable — `readUseEvents` requires an ISO timestamp per event, which is worth remembering when seeding notes.
- **Docs.** Fabric README: an "Inspecting one note" paragraph after `memory:status` (arguments, what each refuse code means, the
  note-level widening limit, legal holds). Both CHANGELOGs.
