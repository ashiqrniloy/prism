# Phase 8 Part B — RAG, wiki, fabric, and context-engineering packages

## Objectives

- Split the rest of the 0.12 `@arnilo/prism-memory` family into native packages under `packages/memory/`:
  - `@arnilo/prism-memory-core`: a plain shared library (contracts, lineage, propagation, ACL, vector stores), if plan 157 Task 1 (d) keeps the default
  - `@arnilo/prism-memory-rag`: retrieval over indexed sources, owning memory's `Embedder` and the `embeddings` service
  - `@arnilo/prism-memory-fabric`: working, semantic, and scoped memory
  - `@arnilo/prism-memory-wiki`: wiki ingest and query with bundled skills, consuming `web.fetch`
- Delete the `@arnilo/prism-memory` workspace.
- Make the kernel's context-engineering modules the native package `@arnilo/prism-context-engineering`:
  - context budget
  - tool-result fold
  - tool search
  - attention compiler

  Each becomes a `context.build` or `compaction.when` handler. The modules, their `AgentConfig` and `RunOptions` fields, and their root exports leave the kernel.
- State in each README the extra model calls, writes, or requests the package adds, and that the costly behavior is off by default.
- Record the Phase 8 Done criteria for the whole phase.

## Expected Outcome

- `packages: [memoryRag({ sources: [...], embeddings: { model: "openai/text-embedding-3-small" } })]` indexes the configured sources. It provides the `embeddings` service, registers a retrieval tool, and (with `context: true`) injects retrieved blocks through `context.build`.
- `packages: [memoryFabric({ ... })]` registers the fabric's working- and semantic-memory tools. It injects its context blocks and gates tool access per session through `SessionContext.entries()` (plan 157 Task 2).
- `packages: [toolsWeb(...), memoryWiki({ wikiRoot: ".wiki" })]` registers the `wiki_*` tools, commands, and skills. With `web.fetch` present, `wiki_ingest` accepts URLs. Without it, URL ingest is off with a status note, and the rest of the wiki works.
- `packages: [contextEngineering({ budget: {...}, fold: {...}, toolSearch: {...}, attention: {...} })]` applies each enabled stage in `context.build`, after every other package's blocks. That closes the plan 145 deferral, where handler-added blocks escaped the budget. The attention compiler requests compaction through `compaction.when`.
- `AgentConfig.{contextBudget,toolResultFold,toolsDisclosure,toolsSearch,attentionCompiler}`, the matching `RunOptions` overlays, and the root exports of `context-budget`, `tool-result-fold`, `tool-search`, and `attention-compiler` are gone. Token estimation helpers the kernel still needs stay, as plan 157 Task 1 records.
- `@arnilo/prism-memory` no longer exists, and the `packages/memory/*` workspace glob covers the five packages plus `core`.
- `pg` is loaded only when a Postgres memory store is configured. The local reranker runtime is loaded only when the local reranker is configured.
- The Phase 8 Done record names the proof for each criterion.

This plan implements roadmap **Phase 8 — Memory and context-engineering packages**, Part B. **Depends on plan 157.** Plan 157 Task 1 is the phase review for both parts, so this plan opens with an entry check instead of a second review. It confirms the review's Part B decisions against the tree as Part A left it. This plan does not bump versions, publish, or edit released `/docs`; those wait for Phase 11. Package READMEs, `docs/next/` pages, and `CHANGELOG.md` `## [Unreleased]` entries are written as each task lands.

Two unusual points:

1. **Package tasks create, then one task retires.** Tasks 3–5 move code out of `packages/memory/src` into new packages one family at a time, migrating each family's importers in the same task. Task 6 deletes what remains of the workspace. The same split applies to context engineering: Task 7 builds the package, and Task 8 removes the kernel modules and their config fields. For one task the algorithms exist both in the kernel and in the package. That is deliberate: the kernel assembly cannot lose them until every caller has a package to list.
2. **Kernel context-engineering removal is a contract change.** It deletes `AgentConfig` and `RunOptions` fields, root exports, durable run-state fields (the attention fold ledger in `src/agent-run-state.ts`), and the kernel-emitted `attention.compiled` event. Task 8 regenerates the kernel baseline and updates the root-export freeze.

Lab impact (probe 12): `packages/prism-code/src/wiki.ts` becomes config for `memory-wiki` in Task 5. `compaction.ts`'s `resolvePrismCodeToolResultFold` and `resolvePrismCodeContextBudget` become config for `context-engineering` in Task 8. Deleting the remaining lab selection logic waits for Phase 12 and goes to Further Actions.
