# Public-Surface Reduction (Dead Exports and Budgets)

Source: `docs/_evidence/implementation-review-2026-09-03.md` §2.2, §4 P2 (budgets),
§8 step 3. `scripts/unused-report.json` currently reports **87 dead-export candidates**
across workspaces; the report is a naive scan, so candidates need verification before
any cut. Follows the versioning policy in `roadmap.md`.

## Objectives

- Verify the 87 dead-export candidates against compat baselines, docs, and external usage; classify keep / deprecate / remove.
- Ship a deprecation wave (marked, documented) and a removal wave in the next allowed breaking cut.
- Add export-count and package-size budgets so the surface cannot silently regrow.

## Expected Outcome

- `scripts/unused-report.json` deadExports → 0 (post-removal) with every kept candidate carrying a recorded justification.
- Public API measurably smaller; `docs/public-contracts.md` and compat baseline reflect the cut.
- Budget gate fails CI if export count or packed size exceeds recorded ceilings.
