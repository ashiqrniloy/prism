# 031 — Release 0.3.0 amendment blueprint: Antigravity CLI + Prism MCP

Roadmap phase: **0.3.x**, proposed amendment to unpublished **0.3.0**.
Baseline: plan 030 complete locally; npm latest remains **0.2.9**; no local `v0.3.0` tag; 56 publishable manifests at 0.3.0.
Status: **complete (2026-08-20) — all Tasks 0–7 finished**.

## Verdict

This blueprint now optimizes for the actual objective:

> Use the Antigravity quota attached to a host’s Google AI Pro subscription while making Prism capabilities available to Antigravity and projecting Antigravity execution into Prism UIs.

The implementation is a **delegated-agent adapter around the official `agy` CLI**, not a Gemini API provider and not a direct Antigravity OAuth client.

- `agy` owns model calls, planning, subagents, checkpoints, and its internal agent loop.
- Prism owns the selected capabilities exposed through an authorized Prism MCP server, plus outer cancellation, deadlines, event retention, redaction, and UI projection.
- `agy --output-format stream-json` provides machine-readable `init`, `step_update`, and terminal `result` events. Prism can show streamed answer text, tool activity, subagents, checkpoints, duration, statuses, and usage—including `thinking_tokens` counts.
- The documented headless stream does **not** expose raw primary-agent chain-of-thought text. Prism must not scrape private Antigravity logs or imply that token counts are reasoning content. UI may show a safe execution timeline and any reasoning summary Antigravity deliberately emits as normal response text.
- Authentication remains entirely inside official `agy`. User authenticates once in an interactive CLI session; headless runs use cached credentials. Prism never reads, copies, refreshes, logs, or transports Antigravity credentials.

Google documents headless mode specifically for scripting, programs, and CI, and documents MCP as Antigravity’s extension bridge. Google also broadly forbids third-party software accessing Antigravity login credentials/service. This design stays on the documented boundaries—official CLI process plus official MCP extension—but public release still needs a recorded terms interpretation or Google confirmation. Direct OAuth/session-token reuse remains forbidden.

## What localharness/CLI loop ownership means

For one delegated run:

```text
Prism host/UI
  ├─ starts and bounds official `agy` process
  ├─ streams safe `agy` NDJSON events into Prism/AG-UI
  ├─ exposes authorized Prism tools through MCP
  └─ stores delegated run + Antigravity conversation ID
       |
       v
Official Antigravity CLI/localharness
  ├─ assembles its model context
  ├─ calls selected Antigravity model
  ├─ plans and chooses next action
  ├─ invokes selected built-in or Prism MCP tool
  ├─ feeds result back to its model
  ├─ manages subagents/checkpoints
  └─ repeats until final result, error, timeout, or cancellation
```

Prism does not select every internal model turn or run Prism compaction/provider middleware between Antigravity turns. This is acceptable for the clarified objective. Every selected Prism tool still executes inside Prism’s existing authorization, guardrail, limit, effect, identity, and redaction path because Antigravity reaches it through `createPrismMcpServer`.

## UI visibility

### Available from documented headless output

Prism can project:

- run start with working directory, selected model/agent, available tool names, and effective Antigravity permission mode;
- incremental assistant response text from `agent_response.text_delta`;
- step index, state (`ACTIVE`/`DONE`), type, and duration;
- built-in and MCP tool name, bounded/redacted parameters, output, and error;
- subagent role/type/status references from `subagent_info`;
- checkpoint activity;
- per-step and final input/output/thinking/cache/total token counts;
- terminal status, response, duration, turn count, conversation ID, and bounded error;
- cancellation, process exit, timeout, malformed stream, and dropped-event status generated by Prism.

### Not available or intentionally withheld

- Raw hidden chain-of-thought for the primary agent is not a documented headless field.
- `thinking_tokens` is a count, not thought text.
- `subagent_info.log_uri` and workspace URIs are path-bearing references. Prism keeps them private by default; a host projector may expose a safe link/path after authorization.
- Interactive Antigravity’s “complete internal thoughts” panel does not authorize Prism to scrape private files or undocumented endpoints.
- Tool parameters/results remain projection-deny-by-default, matching existing AG-UI policy. Host must opt into a safe projector.

UI design: normal answer text uses existing `message_*` events. One additive generic `delegated_agent_step` event carries bounded execution timeline metadata. `@arnilo/prism-ag-ui` maps it to activity/custom events; raw details remain hidden unless explicitly projected.

## Authentication and Google AI Pro quota

- Google documents that Google AI Pro accounts receive higher Antigravity quota, refreshed every five hours until weekly limits are reached.
- Headless `agy` uses cached credentials from a prior interactive `agy` login.
- Prism only executes the official binary and observes documented stdout/stderr/process status.
- If no cached login exists, `agy` exits with `authentication required`; Prism reports a setup instruction to run interactive `agy` once. Prism must not open an OAuth flow itself.
- Prism does not promise a particular model/quota. It records the model selected by `agy` and final usage. Account, geography, current plan, quota exhaustion, and Google-side availability remain host/Google concerns.
- `GEMINI_API_KEY`, Vertex, or Enterprise modes may be documented as separate host-selected fallbacks, but they do not satisfy the Google AI Pro subscription objective and must be labeled separate billing paths.

## Objectives

- Add an opt-in `@arnilo/prism-antigravity-agent` package that runs the official `agy` CLI in documented headless streaming mode.
- Use the host’s existing Antigravity login and Google AI Pro quota without handling credentials.
- Expose selected Prism `ToolRegistry` capabilities to Antigravity through existing `createPrismMcpServer` authorization and limits.
- Support a hybrid tool policy: Prism-first for overlapping mutators, selected Antigravity built-ins where useful.
- Persist explicit Antigravity conversation IDs for continuation; never use global “continue most recent” state.
- Project safe delegated execution events into Prism and AG-UI without claiming access to hidden chain-of-thought.
- Reopen unpublished 0.3.0 without restoring lockstep package versions or adding a preview integration to umbrellas.

## Expected Outcome

Host flow:

```ts
const antigravity = createAntigravityCliAgent({
  command: "agy",
  tools: registry,
  authorize: ({ tool, context }) => authorizeDelegatedTool(tool, context),
  toolPolicy: "prism-mutators",
});

const run = antigravity.run({
  sessionId: "session-1",
  runId: "run-1",
  prompt: "Fix the failing tests",
  cwd: repoRoot,
  model: "gemini-3.5-flash-medium",
  effort: "high",
});

for await (const event of run.events()) {
  await ui.publish(event);
}
```

The adapter launches a bounded official command equivalent to:

```bash
agy -p "<task>" \
  --agent prism \
  --model gemini-3.5-flash-medium \
  --effort high \
  --output-format stream-json \
  --print-timeout 10m
```

For continuation it uses the stored explicit ID:

```bash
agy -p "<next task>" \
  --conversation <validated-conversation-id> \
  --agent prism \
  --output-format stream-json
```

A per-run/workspace MCP configuration points `agy` to an authorized Prism MCP server. Antigravity calls Prism tools; Prism returns bounded MCP results; Antigravity continues its own loop.

## Prism capability coverage

| Prism capability | Antigravity access path | Fidelity |
| --- | --- | --- |
| Tool registry, coding tools, browser, computer use, work tools | Authorized MCP tools | Full tool-call/result fidelity within MCP JSON/schema limits |
| Tool authorization, identity, effects, guardrails, redaction | `createPrismMcpServer` execution path | Full for Prism MCP tools |
| Memory and RAG retrieval | MCP tools/resources or explicit bounded prompt context | Full as callable capabilities; Antigravity chooses when to call |
| Skills/instructions | Generated custom agent instructions and selected MCP tools | Application-level control; Antigravity service scaffolding remains |
| Session continuation | Explicit `conversation_id` / `--conversation` | Full Antigravity continuation; Prism branch semantics need explicit mapping |
| UI text/tool/subagent/checkpoint/usage | `stream-json` projection | Full for documented fields |
| Raw hidden reasoning | Not exposed | Intentionally unavailable; show activity + thinking-token counts only |
| Prism loop strategies/compaction/provider middleware | Outside delegated inner loop | Not applicable inside Antigravity; may wrap outer delegated task only |
| Durable HITL inside a synchronous MCP call | Prism authorization can deny or pre-authorize; exact pause/resume requires proof | Conditional; protected protocol test decides supported shape |
| Prism model router/retry | Can choose CLI model and retry entire delegated run | No control over Antigravity internal model routing/retries |

“All Prism capabilities” therefore means all compatible host capabilities can be offered to Antigravity. It does not mean Prism can replace Antigravity’s private loop machinery while still consuming Antigravity subscription quota.

## Research record

### Official headless CLI

Source: <https://antigravity.google/docs/cli/headless/>

Documented behavior:

- `agy -p` runs one prompt non-interactively and exits.
- Headless mode is intended to “script agent tasks, integrate with CI pipelines, and capture machine-readable output.”
- Headless mode uses cached credentials; unauthenticated non-interactive runs exit with `authentication required` rather than hanging.
- `--output-format stream-json` emits NDJSON: one `init`, zero or more `step_update`, exactly one `result`.
- Step fields include conversation ID, index, state, type, tool name, text delta, duration, usage, `tool_info`, and `subagent_info`.
- Tool info includes name, parameters, output, and structured error.
- Subagent info includes type/role/conversation/log/workspace references.
- Usage includes input, output, thinking, cache-read, and total token counts.
- `--conversation <id>` resumes an explicit conversation.
- `--model`, `--effort`, and `--agent` select execution configuration.
- Headless approvals cannot prompt; tools requiring ungranted approval are soft-denied. `--dangerously-skip-permissions` exists but is explicitly warned against.

### Official MCP integration

Source: <https://antigravity.google/docs/cli/mcp/>

- Antigravity describes MCP as its universal bridge to local tools, databases, parsers, and external APIs.
- CLI supports local stdio and remote HTTP/SSE/Streamable HTTP MCP servers.
- Workspace configuration lives under `.agents/mcp_config.json`; global configuration lives under `~/.gemini/config/mcp_config.json`.
- Config supports `command`/`args`/`env`/`cwd`, `serverUrl`/headers, `disabled`, and `disabledTools`.
- This plan uses a generated local Prism endpoint/config and never edits global user MCP configuration.

### Custom agents

Sources:

- <https://antigravity.google/docs/cli/commands/agents>
- <https://antigravity.google/docs/cli/subagents/>

- CLI discovers workspace agents under `.agents/agents/<name>/agent.md` and global agents under `~/.gemini/config/agents/<name>/agent.md`.
- Agent Markdown uses YAML frontmatter and body instructions.
- Custom agents support specialized system instructions and tool permissions.
- Headless mode selects an agent with `--agent`.
- Switching agents forks Antigravity conversation history; Prism must record returned conversation IDs.

### Plans and authentication

Sources:

- <https://antigravity.google/docs/plans>
- <https://antigravity.google/docs/faq/>

- Individual accounts receive baseline Antigravity quota.
- Google AI Pro receives higher quota refreshed every five hours until the weekly limit; AI Ultra receives the highest quota.
- Headless quota belongs to the authenticated Antigravity account. It is distinct from Gemini API/Vertex billing.
- FAQ recommends Vertex or AI Studio API keys for third-party coding agents and warns against using third-party software with Antigravity login.

### Terms boundary

Source: <https://antigravity.google/terms>

- Users are responsible for agent actions, connected systems/data, fitness, and production supervision.
- Consumer interactions may be retained/reviewed/used under current settings and terms.
- §6 prohibits third-party software/tools/services accessing the Service and names OAuth reuse as an example.
- This design does not implement a client for the Service. It executes the official documented CLI and serves a documented MCP extension. Because the language is broad, Task 0 records product/legal interpretation or Google confirmation before public release.

## Acceptance gates for blueprint approval

Approval means:

1. Antigravity owning its internal loop is acceptable.
2. “All Prism capabilities” means authorized MCP/tool/context capabilities, not replacement of Antigravity internal compaction/model routing.
3. UI shows documented execution activity and thinking-token counts, not raw hidden chain-of-thought.
4. Authentication remains inside official `agy`; host performs interactive login.
5. Public release remains conditioned on a recorded interpretation or Google confirmation that programmatically launching documented headless CLI with cached login is permitted.

## Compromises Made

- Prism no longer owns every model/tool-planning turn; that is required to consume Antigravity subscription quota through the official product.
- Raw hidden thinking is unavailable. UI shows response deltas, execution steps, subagents, checkpoints, durations, and thinking-token counts.
- Some Prism runtime internals—provider middleware, compaction, loop strategy, model router—cannot operate inside Antigravity’s delegated loop.
- Exact durable pause/resume during a synchronous MCP tool approval remains protocol-proof dependent; Prism can always pre-authorize or deny.
- Official CLI binary/login are host prerequisites; package does not install or authenticate them.
- Task 1's deterministic fixture proves the real Prism MCP authorization/stdio path and event bounds. Live `agy` 1.1.16 stream output was also observed, but its unconfigured MCP call was auto-denied by the global permission engine; changing global settings or using `--dangerously-skip-permissions` is out of scope.
- The probe owns temporary workspace config only; it does not prove the final package's per-run config/cleanup until Task 2/3 implement that package surface.
- Google AI Pro account/quota identity is not asserted by the probe; it records CLI protocol behavior only and leaves subscription/terms confirmation as a release gate.
