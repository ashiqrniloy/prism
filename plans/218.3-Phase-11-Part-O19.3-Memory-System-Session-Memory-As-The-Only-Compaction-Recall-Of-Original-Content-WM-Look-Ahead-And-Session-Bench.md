## Objectives

- Make session memory (STM, with WM when on) a compaction system the host turns on or off; when on, it is the **only** compaction of a session that has it on: no kernel trigger, no other compactor, no overflow path that bypasses it. LLM compaction stays the host's other option; one compaction system per agent.
- Fire that compaction on exactly two conditional triggers: **mid-loop** at a share of the model's available context window (default 0.8), and **between loops** at a token cap or a share of the window (default 80,000 tokens), checked only after an agentic loop has completed.
- Remove content from the window **only after STM has recorded it**, and keep the original content (messages, tool calls, tool outputs, file reads) recallable verbatim for the life of the session, resumes included, read from the session store itself rather than from a second copy.
- Keep the request prefix byte-stable between compactions, so prefix caching breaks only at a compaction.
- Fail cleanly on one output larger than the model's window, then compact as if the loop had ended.
- Make WM act on a scope's remaining work: WM runs only under a host-set scope (else the session is STM-only, Task 1 decision 4), a remaining-work view that advances as steps finish, and a look-ahead that brings earlier records and original content forward for the steps still to come.
- Build, freeze and document a project-owned multi-task, same-session benchmark with a scope per session and guardrails against bias, validate it offline, run it live as a test, then run the decision screen: memory-off with Prism's LLM compaction, STM-only, and STM + WM, plus popular third-party memory solutions where their licences and runtimes allow.
- Close plan 218.1; every memory screen runs from this plan.

## Expected Outcome

- With session memory's compaction on (`context.compaction`, default `true`) and memory on for a session, `compaction.when` is answered by session memory on every check; the kernel's default trigger, its `thresholdEntries` trigger and every other compactor never fire for that session. A second compaction system (LLM compaction, context-engineering `fold`/`attention`) beside it fails at agent creation. With `context.compaction: false` the host runs LLM compaction (or the kernel default) instead.
- Config: `context.compaction` (on/off), `context.compactAt.ratio` (mid-loop, default 0.8 of the model's available window) and `context.compactAfterRun` (`{ maxTokens }` default 80,000, or `{ ratio }`), both conditional. `context.compactAt.maxTokens`, `context.trigger` and `context.recentMessages` are retired.
- A compaction never removes an entry STM has not recorded: it first brings STM coverage up to the cut, synchronously, then removes only covered entries; what stays verbatim is chosen by tokens, never splitting a tool call from its result.
- `recall` returns any removed entry verbatim from the session store, paging inside one entry by offset, so an entry larger than any window is still readable in pieces; it works after a resume and after a fork. STM writes no second copy of session content (excerpt chunks retired for the session tiers, per Task 1's decision on the chunk store).
- A prefix-stability test proves consecutive requests share their prefix except across a compaction (the memory block changes only at a compaction, never on an ordinary turn or a background STM pass).
- One output larger than the model's window ends the run with `context_overflow`; the next run starts with a between-run STM compaction that records it and removes it, and the agent can page it with `recall`.
- WM runs only when a host has set a scope (without one the session is STM-only); at every pass it sees the scope, the scope's remaining steps with the finished ones marked from cited passed outcomes, and a bounded set of earlier records (tombstoned ones included) that match the coming steps; it can keep them back into WM, and items tied only to finished steps are released.
- `scripts/memory-bench/session-bench/` holds Session-Bench: a seeded generator of sessions (8–14 user tasks each, one scope document per session) in a simulated, deterministic tool environment, labelled dependency classes, state checks per task, a frozen partition file with hashes, a written methodology, guardrail checks that run before any paid call, and a runner that enforces a simulated model window so sessions outgrow it several times. The model window B lives in the harness, never in the product.
- A live test run (owner-approved budget) on a small dev slice validates the benchmark end to end, checks the live guardrails and sizes the screen; the decision screen (rule and budget approved before the run) compares the arms on the dev partition and leaves held-out partitions for gate A.
- Plan 218.1 is closed (Tasks 1–3 done, Task 4 closed with its findings, Tasks 5–6 dropped by this plan); plan 218 Task 6 reads this plan's screen.
