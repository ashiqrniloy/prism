# Phase 10 Part A — ACP, AG-UI, and MCP-server host libraries

## Objectives

- Review the contracts Phase 10 builds on for both parts: the public `Agent`/`Session` surface, `host.ui` and the kernel's `ask` path, suspension and `session.resume`, and the 0.12 kernel exports each surface uses today. Fix the allow-list that defines "kernel internals" for every host library.
- Ship `@arnilo/prism-acp` with `serveAcp(agent, { stdio })`. ACP permission requests answer the kernel's approval suspensions, and ACP elicitation answers package `host.ui` requests.
- Turn `packages/acp-agent` into a thin binary: `loadManifest()` → `createAgent` → `serveAcp`. Retire `createPrismAcpAgent` and the `@arnilo/prism-ag-ui/acp` subpath.
- Move `@arnilo/prism-ag-ui` to `packages/hosts/ag-ui` as a TypeScript-source host library whose `createAgUiHandler(agent)` drives the public `Session`, not `AgentRunLifecycle`.
- Give `@arnilo/prism-mcp-server` `serveMcp(agent, …)` and retire the direct tool-dispatch server, which runs tools outside `tool.call`.
- Prove the first Phase 10 Done criterion with `examples/acp.ts`.

## Expected Outcome

- `serveAcp(agent, { stdio })` serves any `Agent` over ACP v1. `session/new` and `session/load` map to `agent.session()`. `session/prompt` maps to `session.stream()`, `session/cancel` to `session.abort()`, and `agent.commands` to `available_commands_update`. A tool call that `@arnilo/prism-approval` asks about reaches the client as `session/request_permission` and continues through `session.resume(decisions)` in the same prompt turn.
- An agent created with `host: acpHost()` also gets package `host.ui` requests (`select`, `input`, `confirm`, `notify`) answered through ACP elicitation and session notifications. An agent created without it still gets approvals over ACP. Every other request answers `unavailable`, so it fails closed.
- `examples/acp.ts` runs in-process on the mock provider, connects an ACP client over in-memory streams, approves one tool call over ACP, and exits 0 under `examples_demos_run_to_completion_and_emit_no_secret`.
- `prism-acp-agent` is a binary of about 100 lines that reads the manifest (project scope only after `trustProject` approves it) and serves the agent over stdio. The provider table and config file are gone.
- `createAgUiHandler(agent)` serves AG-UI runs over `agent.session({ id: threadId })`. An approval becomes an AG-UI interrupt, and a resume request calls `session.resume(decisions)`.
- `serveMcp(agent, { stdio } | { http })` serves an agent as an MCP prompt tool. A request for `confirm`/`select`/`input` is answered through MCP elicitation when the client advertises it, and otherwise fails closed. `createPrismMcpServer` is deleted. Phase 14 adds `serveTools(run, …)` to the same library.
- None of the three libraries imports a name outside the Task 1 allow-list, and none constructs an agent.

This plan implements roadmap **Phase 10 — Surfaces and host libraries**, Part A. Plan 162 is Part B (channels, evals, devtools, the repo-wide surface gate, and the Phase 10 Done record) and depends on this plan. Task 1 is the phase review for **both parts**, because Phase 10 may need one kernel addition (Task 1 (c)) and creates or moves host libraries. Roadmap §2.10 lists six `packages/hosts/*` directories; this plan adds a seventh, `packages/hosts/acp-agent`, because the Phase 10 Scope keeps `acp-agent` as its own binary (Task 1 (h) confirms it). This plan does not bump versions, publish, deprecate on npm, or edit released `/docs`. Phase 14 owns `serveTools`. Phase 16 owns `checkpoints` and `leases`, so retired durable-run recovery is recorded in Further Actions, not rebuilt on them. Lab impact (probe 12): `packages/prism-code/src/acp.ts` (519 lines) is reduced in Task 3 to a `serveAcp` call over the lab's assembled agent. Plan 156 (Phase 12) still owns deleting it with the rest of the lab assembly.

## Compromises Made

- **Tool serving waits for Phase 14.** `createPrismMcpServer` dispatched `ToolDefinition[]` outside a run, so approval and governance never fired; it is deleted rather than fixed. `serveMcp` exposes one agent tool, and the MCP tool-surface conformance runner (`scripts/mcp-conformance-2026.mjs` + baseline), the obscura MCP leg, and `resources`/host-registered `prompts`/`agentRuns` lifecycle tools are removed with it. The client-facing fixtures (`mcp-smoke-server.mjs`, prism-code's `echoServerScript`, the phase11 conformance and benchmark fixtures) became plain SDK `McpServer`s so the client-bridge coverage survives.
- **`serveMcp`'s HTTP face is lazy.** `{ http }` returns a plain `(Request) => Promise<Response>` (per the acceptance criteria) whose `createPrismMcpWebHandler` is built on the first request, so a bad HTTP option throws then rather than at `serveMcp`. The SDK `notify`/`bus` faces stay available on `createPrismMcpWebHandler` itself.
- **MRTR approvals need a session.** A suspended run stores its pending decisions in an in-memory map keyed by the MCP session; stdio, in-process, and stateful HTTP resume fine, while a stateless HTTP retry lands on a fresh server instance and fails closed (`ERR_PRISM_MCP_APPROVAL_REQUIRED`) instead of re-running the prompt. Making stateless retries resumable needs `requestState` (integrity-protected) plus a durable `agent.session({ id })` reopen.
- **`{ http }` has no `closed` signal.** For `{ stdio }`/`{ transport }` the handle's `closed` resolves when the transport closes or `close()` is called; for `{ http }` only `close()` resolves it (the web handler has no connection lifetime).
- **`serveMcp` drops the per-call concurrency/timeout ceilings.** `maxPromptBytes`/`maxResultBytes` and the redactor stay; concurrency and request timeouts are the HTTP transport helper's own bounds, and stdio has none.
- **`docs/options-index.md` loses its MCP row.** `CreatePrismMcpServerOptions` is deleted and released `docs/mcp-tools.md` names no live option type, so the row was removed rather than repointed; the MCP pages stay unindexed until the docs are rewritten for `serveMcp`.
- **`packages/hosts/acp/src`'s non-null row was corrected 1 → 16.** Task 3's ported ACP test files carry index/optional accesses the row missed; the ceiling check would otherwise fail for a Task 3 change.
