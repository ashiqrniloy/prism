# Phase 11 Part O.1 — memory fabric: OKF markdown as the source of truth, lexical retrieval first

## Objectives

- Make long-term fabric memory inspectable. Every durable note is an OKF v0.2 markdown file a person can read, grep, edit, diff, and delete. Every index is a rebuildable cache over those files.
- Retrieve lexically by default: BM25 over a derived SQLite FTS5 index, with the agent driving the search (memory directory → `memory.recall` ranked snippets inline → `memory.read`). Embeddings become an optional, derived, off-by-default hybrid leg.
- Handle the known risks of lexical, file-based memory, each with a mechanism and a test:
  - vocabulary mismatch
  - the token cost of agentic search
  - concurrency and atomicity
  - server and Postgres deployments
  - scale
  - memory poisoning
  - superseded notes that still match lexically
- Build the benchmark configurations for plan 188's measurement work (its Task 14): lexical vs hybrid vs agentic, paired on the same questions. The run itself moved to plan 188.6 (amendment 2026-10-19) so it measures the full memory lifecycle.
- Fix the lifecycle defects that would bias that measurement (D4, D5, D9, D13), and lay out durable notes by scope rather than by thread (amendment 2026-10-19).

**Evidence for the change** (owner-reviewed analysis, 2026-10-19):

- **Inline lexical search is a strong default when an agent drives retrieval.** Inline grep beat inline vector retrieval in 10/10 harness × model pairs on LongMemEval-S (Sen et al., arXiv 2605.15184). Programmatic (file) delivery reversed that in 5/10 pairs.
- **A file-based design can match or beat dedicated memory systems.** Letta's filesystem agent scored 74.0% on LoCoMo against Mem0's then-reported 68.5%. ByteRover uses markdown with BM25 and no embeddings and self-reports 96.1% LoCoMo and 92.8% LongMemEval-S (arXiv 2604.01599). Its largest ablation (−29.4 pp) is tiered retrieval and escalation, not the ranker.
- **Single-vector embeddings have hard limits.** On LIMIT, BM25 scores R@2 85.7 and single-vector embedders score ≤3.0 (Weller et al., ICLR 2026).
- **Counter-evidence: dense retrieval still wins on single-shot paraphrase recall.**
  - LongMemEval App. E.2: Stella session R@5 0.720 vs BM25 0.634.
  - agentmemory: BM25 86.2% vs hybrid 95.2% R@5.
  - BM25 degrades on synonym substitution (LIMIT variant).
  - So the vector leg stays available, and this plan's final task decides its default by paired test.
- **The gap closes with write-time key expansion and query-time expansion.**
  - LongMemEval fact-augmented keys: +9.4% recall.
  - query2doc (EMNLP 2023): BM25 +3–15%.
- **Agentic search has its own costs.** Index-free deep agentic search lost to a vector index on code QA (46.2% vs 65.2%, arXiv 2608.01507), and 41.8% of its failures were planner/subagent handoffs. So retrieval stays in-process and ranked; it is not delegated.
- **Memory poisoning is practical.** MINJA reports 98.2% injection success through queries alone (arXiv 2503.03704). Auditable files, provenance, and candidates matter.

## Expected Outcome

- With `tools.root` set, the fabric's default store is `"markdown"`. Its layout, under `<tools.root>/notes/` by default:
  - `index.md`: OKF root index, `okf_version: "0.2"`, regenerated on writes.
  - `log.md`: newest-first audit log of writes, corrections, forgets, archives, and external edits. Holds ids and verbs, never note text.
  - `<tenant>/<resource-path>/{facts,procedures,episodes}/<slug>--<id8>.md`: one note per file, OKF concept frontmatter, the note text as the body.
    - `<resource-path>` is the `resourceId` split on `/`, so plan 188.2's scope hierarchy (`user`, `agent`, `projects/<slug>--<id8>`) maps onto directories without a layout change. Each segment is validated.
    - The thread is **not** a path segment: durable notes outlive sessions. It is kept in frontmatter as `prism.thread_id` and as provenance (`sources[].resource: prism-session:<id>`), and the index filters on it.
  - `<tenant>/<resource-path>/archive/...`: superseded, expired, and archived notes.
  - `<tenant>/<resource-path>/working/<thread>.md`: working-memory blocks (working memory is per thread).
  - `<tenant>/<resource-path>/.state.json`: non-derivable control state, keyed by thread inside the file: invalidations, legal holds, share grants, source access grants, generation.
  - `.index.sqlite`: the derived FTS5 BM25 index, with optional embeddings. Deleting it loses nothing; the next open rebuilds it from the files.
  - Writes are atomic (temp file + rename) under a cross-process lock. Files are written first and win, so a crash between file and index is repaired on the next open.
  - A file edited by a person is re-indexed on open or on `memory:reindex`, scanned for injection, and logged.
- Retrieval:
  - `retrieval: "lexical"` is the default; `"hybrid"` adds the embedding leg through the `embeddings` service.
  - Semantic notes no longer need an embeddings package.
  - Every [0,1] threshold (consolidation, the inject floor, scoped activation) uses the active mode's similarity: query-term coverage or term-set Dice for lexical, cosine for hybrid.
  - Lexical terms are stemmed and stopword-filtered identically for indexing, BM25 queries, and coverage.
  - The FTS index weights note keys (keywords, aliases, tags, title, context) above the body.
- `memory.recall`:
  - available without embeddings
  - accepts `queries: string[]` (up to 4) fused by RRF, so the agent can try synonyms in one call
  - returns ranked snippets inline under a token budget, each with id, kind, date, note path, and matched terms
  - says when results are empty or weak, so the agent can reformulate
- Notes carry provenance (`generated.by`: agent | promotion | human | import; session id; source entry ids).
  - Injection-flagged human edits become candidates with `flags`; they are never passively injected and are marked in recall output.
- `memory:export` and `memory:import` move any store (memory, SQLite, Postgres, markdown) to and from an OKF bundle. This is how server deployments get inspectability.
- `scripts/memory-bench/markdown-scale.mjs` measures open/rebuild/write/recall at 1k, 10k, and 50k notes. The fabric README states the supported scale.
- The benchmark gains `fabric`, `fabric-hybrid`, and `fabric-agentic` configurations. The rerun and ablations of plan 188 Task 14 move on to plan 188.6, which runs them once the memory lifecycle (plans 188.2–188.5) has landed.
- Four lifecycle defects found by the 2026-10-19 memory-lifecycle analysis are fixed here so later work does not build on them (Task 3 and Task 11):
  - D4: superseded OM reflections leave their promoted notes active.
  - D5: candidates are verified by being retrieved, not by being used.
  - D9: the scoped read path skips its floor for lexical hits.
  - D13: archiving sets `validTo`, conflating "not used lately" with "no longer true".
