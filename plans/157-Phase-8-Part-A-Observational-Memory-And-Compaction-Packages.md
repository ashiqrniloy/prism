# Phase 8 Part A — Observational memory and compaction packages

## Objectives

- Run the Phase 8 review for both parts. It inventories the 0.12 memory family and the kernel context-engineering modules, classifies every Scope bullet, and records the decisions both parts build on.
- Add the two kernel seams that observational memory (OM) and the memory fabric need and that no existing seam expresses, if the review confirms them:
  - read-only access to the session branch from a package
  - the compaction slot owner's session view inside `compact()`
  - (conditional) append-only package records for ledgers larger than one 64 KiB state value
- Make LLM summary compaction the native package `@arnilo/prism-memory-compaction`, which claims the `compaction` slot.
- Make observational memory the native package `@arnilo/prism-memory-observational`:
  - separate observer and reflector models through `prism.models.client`
  - a per-session toggle in session state
  - `/om` and `/om:model` commands, plus the 0.12 `om:status` and `om:view` commands
  - a `recall` tool visible only when OM is on
  - observation injection in `context.build`
  - background observation after `turn.completed`
  - observation- and reflection-based compaction in the `compaction` slot
  - `om.*` status events
- Retire the `@arnilo/prism-memory/compaction/{llm,observational-memory}` subpaths and the host-side OM coordinator in the lab.
- Prove the three Phase 8 Done criteria with an example on mock providers.

## Expected Outcome

- `packages: [memoryCompaction({ model: "mock/summary" })]` makes `session.compact()` and auto-compaction write an LLM summary. Its summary call runs through `prism.models.client` on the configured model.
- `packages: [memoryObservational({ observer: { model: "mock/observer" } })]`:
  - registers the `om`, `om:model`, `om:status`, and `om:view` commands
  - toggles OM per session through `agent.commands.run("om", {}, { session })`
  - shows `recall` only on sessions where OM is on
  - injects observations through `context.build`
  - runs the observer as a tracked background task after each turn, on its own model
  - compacts with observations and reflections when it owns the `compaction` slot
  - emits `om.status` package events
- Listing `memory-compaction` and `memory-observational` together fails `createAgent` with `SlotConflictError` (`ERR_PRISM_SLOT_CONFLICT`) until `AgentConfig.slots.compaction` or the manifest names the owner.
- A session with OM on, reopened in a new process through a durable store, still has OM on, its observer model, and its ledger.
- `examples/observational-memory.ts` proves all of the above under the execution gate. Its host code contains no OM logic.
- `packages/prism-code` lists the OM and compaction packages instead of building `ObservationalMemoryCoordinator` and `resolvePrismCodeCompaction`'s compactors itself. Its TUI `/om*` commands dispatch to `agent.commands`.
- `@arnilo/prism-memory/compaction/llm` and `@arnilo/prism-memory/compaction/observational-memory` no longer exist. Their importers are migrated and the baselines regenerated.

This plan implements roadmap **Phase 8 — Memory and context-engineering packages**, Part A. **Part B is plan 158**, which depends on this plan. Task 1 is the phase review for both parts, because Phase 8 adds kernel contracts (Task 2) and creates and moves packages. Part B opens with an entry check instead of a second review. This plan does not bump versions, publish, or edit released `/docs`; those wait for Phase 11. Package READMEs, `docs/next/` pages, and `CHANGELOG.md` `## [Unreleased]` entries are written as each task lands.
