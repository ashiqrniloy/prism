# Phase 11 Part O19.4 — Memory system: remove working memory

> **On hold, owner 2026-11-22:** "if we are being too casual about dropping WM … I would design a second benchmark for testing this before the drop decision." This plan waits for plan [218.5](218.5-Phase-11-Part-O19.5-Memory-System-STM-Recording-Fixes-And-A-Long-Session-Bench-That-Decides-Working-Memory.md)'s verdict (Task 8): on a drop verdict it runs as written (WM's mechanical fixes from 218.5 Task 3 leave with WM); on a keep verdict it is closed `superseded by 218.5`.
>
> **Owner decision, 2026-11-21:** "I would then drop WM." Then: "run the STM D2 replay and plan WM removal separately."
>
> The decision followed plan 218.3 Task 12's Session-Bench screen and a WM diagnostic.
>
> **The screen** (rule `a1c6df8d`, interim read on 35 paired sessions):
> - STM+WM − STM-only on pooled dependency checks: −0.01 [−0.10, +0.08].
> - Control checks: −0.03 [−0.07, +0.02].
> - Cost: 1.26× STM-only's input per passed task.
> - WM fails the pre-registered default rule.
> - By class: WM gained on D4 (superseded values, +0.20 [+0.06, +0.37]) and lost on D2 (user-only rules, −0.21 [−0.42, 0]).
>
> **The diagnostic** (four replays, scratchpad only, counts and findings recorded here):
> 1. WM's `supersedes` check ignores constraint protection (`packages/memory/system/src/session/workers/wm.ts:195`). A WM summary or fact replaced protected constraint events twice in one session. The rule then survived only as the tail of a "Task 2 done" status line, and the agent created a ticket without the label.
> 2. WM writes wrong or stale facts rated high or critical: "ship Thu" where the user changed the day to Tuesday, and a stale document's day promoted to a fact. `render.ts` `orderWmItems` puts facts first, above the correct source records.
> 3. At Session-Bench lengths the STM surface never comes under pressure. STM-only's memory block reaches about 12K characters by the last task, so WM's compression has nothing to compress.
>
> **Depends on:** plan 218.3 Tasks 12–14. Task 12 writes the screen evidence. Task 13 closes plan 218.1 and plan 218 Task 6 (gate M-2). Task 14 amends the roadmap and the design record. This plan amends Task 14's scope to record the decision (Task 1 below verifies it landed).
>
> **Runs before:** plan 219. Plan 219's Rehearsal reads WM today; Task 6 below re-cuts it to read STM.

## Objectives

- Remove working memory from `@arnilo/prism-memory-system`:
  - the worker
  - the pass inside the flush
  - its config, ledger records, protections, salience and look-ahead
  - the scope step machinery that only orders WM items
  - the WM branches of render, recall, compaction, commands and the service
  - no compatibility alias (roadmap rule)
- Keep everything STM-only uses working and byte-stable except the deliberate render change, including:
  - the STM pass and its retry and fallback records
  - compaction as the session's only compaction
  - `recall` of original content
  - prefix stability between compactions
  - the episode scope text that Rehearsal (plan 219) and priming (plans 219.1, 220) read
- Retire the LTM paths that read WM items: gather's `reflection` source, `remember({ reflectionId })`, superseded-reflection handling, and the consolidation trigger keyed on WM items.
- Re-cut plans 219, 219.1, 220, 221 and 223 so Rehearsal and later tiers read STM directly. Close the WM-only open work in plans 218 and 218.1.
- Retire WM's benches, probes and criteria rows. Keep every evidence file as written.

## Expected Outcome

- No module under `packages/memory/system/src` imports or names WM. `MEMORY_SYSTEM_COMPONENTS` is `["stm", "rehearsal", "ltm"]`. A config with `wm` fails with the package's named config error and names the key as retired.
- The session memory block and the compaction summary no longer carry a `## Working memory` section. `FoldedMemoryDetails` drops `wmItems` (version 3). A version-2 payload still reads, with its items ignored.
- An old session ledger that holds `memory.session.wm.recorded` and `memory.session.observations.tombstoned` records still folds and resumes. WM's records are ignored, and records WM tombstoned return to the STM surface.
- Session-Bench offline runs every remaining arm green. A live STM-only check on the three validation sessions matches the screen's STM-only rate within its noise. This check is paid, on the owner's word.
- Plans 219–223 describe STM → Rehearsal → LTM. The compat baseline, retired-names sweep, host-builder kit, examples, docs and the reference host carry no WM name.

This plan changes the memory package's public surface (removals only) and its config contract; it changes no kernel contract, so Task 1 is a review of the removal's boundary rather than a kernel-contract review. The memory packages are on the experimental line (plan 215), so removals classify as non-failing in the compat gate, but the baseline is still regenerated and the diff attributed. No version bump, publish or `/docs` kernel page change ships; `docs/limits.md` and `docs/migrate-to-0.13.md` carry package-level text that is edited. The STM D2 finding (rules said in passing are sometimes never recorded; see Further Actions) is not in this plan's scope.
