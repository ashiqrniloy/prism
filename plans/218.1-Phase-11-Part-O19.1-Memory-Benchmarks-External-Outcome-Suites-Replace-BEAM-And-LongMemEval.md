# Phase 11 Part O19.1 — Memory benchmarks: a lean external screen replaces BEAM and LongMemEval

## Objectives

- Remove `beam-1m` and `longmemeval-m` from every memory-model gate (owner decision, 2026-11-12). They measure question answering over imported chat logs, not the work Prism's memory does: keeping a coding agent's progress across compaction. At about 1M tokens a question, they also cannot reach a sample size that decides anything (gate M-1: 2 questions per cell; gate M-2: 4).
- Answer the question that matters now, cheaply and quickly, on an external benchmark we did not design: **is STM + WM worth shipping as the session memory, over no memory, the pre-redesign observer, STM alone, and a production agent's own compaction prompt?**
- Defer everything a cheap screen cannot settle: the second model, held-out partitions, long-term memory suites and the full gate A. These run only if and when the owner chooses to spend on them.

## Expected Outcome

- `memory-model-criteria.json` amendment 6 removes the two suites from every row. Rows whose new suite is deferred read `missing` until it is adopted, never `pass`.
- `scripts/memory-bench/external/compact-bench/` holds a pinned adapter: Prism as the method under test, plus a Messages-to-Chat bridge so an OpenCode Go Chat-route model can be the continuation agent.
- One **lean screen** (Task 3), with its decision rule written into the gate record before the run:
  - a retention screen on 30 sessions;
  - an outcome screen on the 22 validated repair tasks;
  - one model family, OpenCode Go only, **about $6–12 and half a day of runs**.
- Plan 218 Task 6 (gate M-2) reads the screen in place of M5 and runs no QA suite job.

This plan implements the owner's benchmark decisions of 2026-11-12, made after plan 218 Task 6's first sitting. It runs before Task 6 resumes. **No review task:** it changes no product contract, only the bench harness, the criteria file and the evidence. No version bump and no publish. **Claude Code is not used** for any benchmark call (owner, 2026-11-12: its system prompt would be part of what is measured). `locomo` and `memoryagentbench-cr` (also QA) stay where plans 219.1 and 222 use them until the owner decides.

**Survey (2026-11-12).** Candidates were read at their primary sources:

| Benchmark | Verdict | Why |
|---|---|---|
| Compact-Bench (arXiv 2610.31710; [code](https://github.com/cai-jianfeng/compact-bench) and [data](https://huggingface.co/datasets/caijanfeng/compact-bench) Apache-2.0) | **adopt (this plan)** | Scores what compaction costs a coding agent. **Task preservation:** a frozen SWE-bench repair continues from the full history (PRE) or from the compacted state only (POST), judged by the repo's FAIL_TO_PASS tests, with `redo_reads` counted (our re-derivation signal); 35 tasks, 22 validated. **Recurring-detail retention:** 146 sessions, 9,330 annotated details, scored by literal string match with no model. It compares five production compaction prompts (Claude Code, Codex, opencode, Gemini CLI, Kimi Code) and a free regex reference (`anchor_index`: 79% retention, against at most 16% for LLM summaries). The method under test is anything that maps a history to a summary (`harness/e1_runner.py` and `harness/e2_score.py` `compress`). |
| MemoryArena (ICML 2026; data CC-BY-4.0, code licence not stated) | **deferred** | Declarative long-term memory across interdependent sessions; for plans 219+. |
| STATE-Bench Agent Learning Track (Microsoft, MIT) | **deferred** | Cross-task learning with deterministic state checks; for plans 220–221. |
| LoCoBench-Agent (Salesforce, Apache-2.0) | **reject** | Heuristic metrics (`locobench/evaluation/bias_free_evaluator.py`). Memory retention counts words such as "previously" plus vocabulary overlap, floored at 0.3. Task completion is self-reported. No tests run. |
| CompactionBench (Microsoft Research) | **watch** | Repeated compaction plus prefix-cache reuse; no code or data found. |
| DolphinBench (Mem0), Letta Context-Bench | **not adopted** | Vendor-authored by memory-product companies. |

      1. Replay H through an agent session with the arm's memory configuration (`session-replay.mjs`).

  - Acceptance Criteria:
    - Functional: **Gate record first.** `docs/_evidence/memory-bench/218/gates/owner-gate-m2.json` is amended with the routes, the draw hashes and the decision rule below, and approved on the owner's word before any paid call. A changed rule after the run is refused.

      - Memory worker and summarizer for every arm and reference: `muse-spark-1.3-contributor`.
      - Continuation agent: `deepseek-v4.1-flash` with thinking off, through the bridge.
      - No judge model: both scores are deterministic.
    - Functional: **Retention screen.**
      - 30 sessions × arms `memory-off`, `OM-before`, `STM-only`, `WM`;
      - references: the Claude Code and Codex compaction prompts on Muse, and `anchor_index`.
      - Paired per session. The estimate is WM minus each comparator, in points of retained details, with a cluster interval.
    - Functional: **Outcome screen.**
      - 22 tasks × PRE, `memory-off`, `WM` and the Claude Code prompt: 88 continuation runs, one round, 8 steps.
      - POST pass counts, `redo_reads`, and the McNemar-style discordant pairs WM vs each comparator.
    - Functional: **Decision rule (pre-registered).**
      - **Ship STM + WM as the session default** if:
        - WM's retention is non-inferior to the Claude Code prompt (interval lower bound ≥ −5 points), **and**
        - WM's retention beats memory-off (interval lower bound > 0), **and**
        - on the 22 tasks, WM passes at least the Claude Code prompt's count minus 1.
      - **If WM does not beat STM-only on retention** (interval includes 0), the deterministic WM policy becomes the default: same retention, no model calls.
      - **If WM loses clearly** (interval upper bound < 0 against the Claude Code prompt or `anchor_index`), the finding goes to the owner before any plan builds on WM.
    - Functional: the screen's report says what it cannot show:
      - one model family;
      - 30 sessions and 22 tasks, which detect large differences only;
      - no long-term memory;
      - the 22 tasks are no longer held out.
    - Performance: about $5 for the retention screen and about $1 for the outcome screen at the measured rates. About 2–3 hours of retention replay plus 2–3 hours for task environments and continuations. Reports tokens, cost and p95 per arm.
