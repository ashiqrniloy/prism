# Phase 11 Part O19.1 — Memory benchmarks: a lean external screen replaces BEAM and LongMemEval

> **Amended 2026-11-13 (owner, memory evaluation; design §14):** Task 3's Step 1 probe, running on 2026-11-13, finishes unchanged. Step 2 (the paid screen) waits for [plan 218.2](218.2-Phase-11-Part-O19.2-Memory-System-Session-Tier-Hardening-For-Small-Workers-Durable-Signals-Recall-Query-Verdict-Format-And-Baseline-Arms.md), which changes the STM and WM workers the screen would measure. After plan 218.2 Task 9 the probe is re-run on the new product hash, and that reading selects the branch. Both branches gain a `mask-tail` reference.

> **Amended 2026-11-17 (owner, benchmark decision after Task 3's interim read):** Compact-Bench measures literal retention, so it cannot say whether WM helps an agent finish its work, and its task track is too short for WM to engage. The owner chose external agentic benchmarks instead of our own authored screen:
> - **LOCA-Bench** (HKUST, ICML 2026, MIT; [paper](https://arxiv.org/abs/2602.07962), [code](https://github.com/hkust-nlp/LOCA-bench)) **decides the session default** (Tasks 4–5). It scores task success with tools while the environment grows past the context budget, so compaction must fire, and it has published same-protocol baselines (ReAct, tool-result clearing, observation masking, LLM summary, Context-Folding, Claude Code; [VISTA, Table 1](https://arxiv.org/pdf/2606.30005)). It replaces gate M-2's self-authored `long-horizon` family as the reading behind the WM default rule (plan 218 Task 6), and that family is deleted in Task 5.
> - **τ-bench under compaction** (Task 6) measures **policy survival**: whether rules given in the session still govern the agent's actions after compaction, following the protocol idea of [The Compaction Cliff](https://arxiv.org/abs/2608.22752) (CIKM 2026). It reads a new row, S5.
> - **Task 3 finishes as run**, but its verdict becomes a **diagnostic**: M5 (literal retention) and its owner findings are reported; the ship rule written for it no longer sets the session default. The gate record's `compactBenchScreen` carries this amendment, made before the final scoring.
> - **Long-term memory:** MemoryArena stays where plans 219, 219.1, 221 and 223 already use it; **AMA-Bench** ([paper](https://arxiv.org/abs/2602.22769), ICML 2026: memory over agent trajectories) is added to plans 219 and 219.1 (development) and 223 (held-out).
> - **Publication-grade protocol.** If the memory model works, the evidence is meant to support a research paper, so every external screen here runs its baselines on the same model as Prism (published numbers from other models are context only), fixes its rule and partitions before any paid call, reports intervals, and keeps a held-out partition for gate A. A second model and more seeds are named in each task as the owner's option.

## Objectives

- Remove `beam-1m` and `longmemeval-m` from every memory-model gate (owner decision, 2026-11-12). They measure question answering over imported chat logs, not the work Prism's memory does: keeping a coding agent's progress across compaction. At about 1M tokens a question, they also cannot reach a sample size that decides anything (gate M-1: 2 questions per cell; gate M-2: 4).
- Answer the question that matters now, cheaply and quickly, on an external benchmark we did not design: **is STM + WM worth shipping as the session memory, over no memory, the pre-redesign observer, STM alone, and a production agent's own compaction prompt?**
- Defer everything a cheap screen cannot settle: the second model, held-out partitions, long-term memory suites and the full gate A. These run only if and when the owner chooses to spend on them.
