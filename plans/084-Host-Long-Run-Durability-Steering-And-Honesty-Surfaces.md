# Host Long-Run Durability, Steering, and Honesty Surfaces (G1–G7)

Status: complete (2026-09-17). Derived from the 2026-09-17 Synapta host review (`~/Projects/synapta-core/docs/architecture/prism-070-and-agent-desk-review.md`, `plans/117-Prism070Adoption.md`, `docs/architecture/synapta-agent-mechanism.md` §9). Closes the seven gaps (G1–G7) identified for Synapta as Prism's major embedded host. Release vehicle: **0.8.0** via [085](085-Honesty-Gates-Runtime-Split-And-0-8-0-Cut.md), additive-only, zero removed exports.

## Objectives

- **G1:** Let a host run a long single-run investigation (Do-style `singleShotLoop` under an external orchestrator such as Temporal) survive process restart mid-run and resume "continue thinking" from a durable checkpoint without re-dispatching tools or re-running the model from turn zero.
- **G2:** Give hosts run-level stop/steer policy at provider-turn boundaries — stop for L1 "first plan paint" as *run policy* with a distinct stop reason, not a `maxTurns` error and not prompt text.
- **G3:** Formalize a server-authoritative AG-UI handler mode where client-posted state/tools are validated-and-ignored, so hosts do not write per-relay shims (Synapta T21 `ERR_PRISM_AG_UI_INPUT` class).
- **G4:** Emit a versioned, content-addressed **effective run bundle** snapshot (prompt contributions, skill/playbook catalog, tool schemas, `thinkingLevel`, resolved run limits, attention/memory config, provider settings) for host harness pinning and diffing.
- **G5:** Ship a composable evidence-grounding output guardrail primitive: numeric/quantitative claims must bind to cited tool-result evidence; ungrounded claims block or flag.
- **G6:** Classify provider failures (quota / auth / transient / permanent) as typed, budget-classified outcomes surfaced on run results and the run ledger.
- **G7:** Add conformance-derived, machine-readable tool-call reliability metadata to the model registry plus a documented per-provider behavior matrix, so hosts pin models on evidence.

## Expected Outcome

- A host can: adopt `checkpointPolicy: "every-turn"`, crash its worker between provider turns, call `resumeAgentRun(ref, { decision: "continue" })` in a new process, and continue the investigation with no double-appended tool results (`docs/durable-runs.md` recipe + `examples/durable-investigation.ts`).
- A host can stop a run at a turn boundary for policy reasons and read `stopReason: "host_policy"` (distinct from `max_turns`) on the run result, timeline, and ledger; mid-run `steer()` already exists and is exercised in the same recipe.
- `createAgUiHandler` accepts an input policy that ignores client-posted `state`/`tools` server-side with bounded validation, and a conformance test proves a state-posting client cannot alter the run.
- `snapshotRunBundle(...)` returns a frozen JSON document plus digest; two sessions with identical configuration produce identical digests; any contribution change changes the digest.
- A guardrail built from the new primitive blocks a response asserting an uncited total while passing the same figure when cited to the emitting tool result (fixture-proven).
- A provider 429/quota failure surfaces as a typed `ProviderQuotaError`-class outcome on the run result and ledger entry, not an opaque upstream string.
- The model registry exposes advisory tool-call strictness metadata and `docs/model-registry.md` carries the per-provider matrix with conformance evidence links.
