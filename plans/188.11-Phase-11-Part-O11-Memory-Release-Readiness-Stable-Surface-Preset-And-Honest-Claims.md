# Phase 11 Part O11 — Memory release readiness: a stable host surface, the conversational preset, cross-model evidence and honest claims

## Objectives

- Ship the memory system in 0.13.0 with a **host surface that later memory work cannot break**. The robustness work that follows inside 0.13.0 (plan 202, release step 17b), and every later release, must land without a host rewriting its config, its approval rules, its store, or its imports. Concretely:
  - one config line selects the measured behaviour: `preset: "conversational"`;
  - the fabric, core and observational root exports shrink to what a host or store author needs; prompts, tuning constants and scoring helpers stop being public API;
  - note files written by 0.13.0 stay readable by later versions, and notes written by later versions are preserved — never deleted — by 0.13.0;
  - the store, embedder, tool, command and config compatibility rules are written down and enforced by tests, ahead of plan 185's surface freeze.
- Leave the tree and the plan index true:
  - the kernel tarball ceiling is measured on the committed tree, not on another session's uncommitted docs;
  - 188.6 Task 6 and 188.7 Task 8 are closed with pointers to their successors;
  - the stale `planned` statuses of 188.2–188.7 in the index are corrected;
  - 188.10's read-side time overrun is recorded as a compromise.
- Measure, free and before plan 202's paid baseline, how often the trust scan refuses ordinary conversation turns. The cross-family and multi-model evidence belongs to plan 202 Tasks 3–4, which run inside 0.13.0.
- Make the reference host adopt the preset in one line, with an offline scenario. Add memory to the live release journey (plan 186) and give the fabric and OM live rows on supported providers.
- Make every claim in the tree match the evidence until plan 202 replaces it: non-inferiority on one model, not "better than full context"; passive-only is weaker than full context; OM has no quality evidence. The open findings F3, F4, F7 and F9 go into a Known limitations register. Plan 202 Task 16 closes each entry or carries it into the 0.13.0 README.

## Expected Outcome

- `memoryFabric({ preset: "conversational", tools: { root } })` resolves to exactly the configuration that passed 188.10 Task 9. Explicit fields override preset values. An unknown preset fails with `MemoryValidationError`. `memory:status` reports `preset: "conversational"` and `presetRevision: 1`.
- `packages/memory/fabric/README.md`, `packages/memory/core/README.md` and `packages/memory/observational/README.md` each have a `## Compatibility` section stating:
  - which exports, config fields, tool names, command names and file formats are stable at API level 1;
  - what a later minor version may change (ranking, budgets, prompt text, tool descriptions, preset contents within the preset contract);
  - what needs a new preset name or an explicit opt-in field (a new storage class, new write-path model calls).
- The three memory compat baselines are regenerated after the export reduction. Each removal is attributed to this plan, and the root-export freeze test covers them.
- A future-version note (`fabric.v: 2`, unknown fields) survives reconcile, reindex, maintain and export byte for byte. It is excluded from recall and counted in `memory:status` as `unreadable`; it is never deleted.
- `bun scripts/release.mjs gate`'s kernel budget passes on a clean worktree of `HEAD`, and its `$comment` explains every byte.
- The reference host has a `memory: "conversational"` agent option and an offline scenario. It also has a live-matrix row `memory/fabric-conversational-live`. The OM live row points at a supported provider. Plan 186 Task 3 lists an eleventh scenario, memory across sessions.
- `docs/_evidence/memory-bench/188.11/` holds the trust-scan false-refusal and detection measurement, and `limitations.json`, the register plan 202 works through.
- The fabric README's conversational-preset section, the CHANGELOG and `docs/_evidence/memory-bench-0.13.0.md` state the claim the 188.10 evidence supports, plus the Known limitations register.

This plan is a pre-publish part of roadmap **Phase 11** (memory, Part O, sub-part 11). It runs as release step **4l**, after 188.10 and before 189, because Task 5 changes the export surface that plan 185 freezes, Task 3 adds a config field the reference host adopts, and plan 202 (step 17b, also in 0.13.0) builds on the preset contract and stability rules set here. **Review task included** (Task 1): the plan changes package contracts (exports, a config field, the note-reader rule), creates or moves no package, and changes no kernel contract. No version bump, publish, or `/docs` page. **No paid call.** The cross-family re-judge and multi-model replication this plan first carried moved to plan 202 Tasks 3–4 when the owner decided on 2026-10-24 that plan 202 ships in 0.13.0. Defaults do not change here: the preset is opt-in, and plan 202 Task 19 settles the default-on question before publish.
