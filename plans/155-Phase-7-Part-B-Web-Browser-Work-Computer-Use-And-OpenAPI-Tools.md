# Phase 7 Part B — Web, browser, work, computer-use, and OpenAPI tools

## Objectives

- Make the remaining tool families native packages under `packages/tools/`:
  - `@arnilo/prism-tools-web`: search, fetch, and extract over Brave, Exa, Firecrawl, and Obscura, selected by config, providing the `web.fetch` service
  - `@arnilo/prism-tools-browser`: Playwright automation
  - `@arnilo/prism-tools-work`: Office documents, sheets, diagrams, the document reader, and the M365 and Google connectors, with their skills
  - `@arnilo/prism-tools-computer-use`: Linux desktop control, gated through `tool.call`
  - `@arnilo/prism-tools-openapi`: tools generated from OpenAPI specs
- Make "cannot operate" a status note, never a failure. A missing key, binary, or optional module registers nothing and calls `status.note(...)`, and the agent still runs.
- Load each heavy dependency (`playwright-core`, `@office-open/*`, `mammoth`, `pdf-parse`, `@firecrawl/anydoc`) only inside its owning package, and only when that package is listed.
- Retire the `@arnilo/prism-web-tools` and `@arnilo/prism-work` workspaces, the `/openapi` and `/computer-use-linux` subpaths of `@arnilo/prism-coding-tools`, and the kernel's `ExecutionPolicy` export.
- Prove the fourth Phase 7 Done criterion: `tools-web` with no key yields a note and a working agent.

## Expected Outcome

- `packages: [toolsWeb({ backend: "brave", apiKey: "env:BRAVE_API_KEY" })]` registers `web_search`, `web_fetch`, and `web_extract` (as the backend supports them) and provides `web.fetch`. With `BRAVE_API_KEY` unset, `agent.inspect()` shows a warn note, no web tool is registered, and a run completes.
- `toolsBrowser()` registers the browser tools. An agent that does not list it never loads `playwright-core`, and an agent that lists it without Playwright installed gets a note instead of a throw.
- `toolsWork({ root })` registers the Office, sheet, diagram, and document-reader tools and adds its bundled skills. Connectors register only with ref-only credentials. An agent that does not list it loads no Office parser.
- `toolsComputerUse()` registers the desktop tools only where the backend binary probes, and its `tool.call` handler denies the action classes that 0.12 classified as denied.
- `toolsOpenapi({ specs })` turns each spec into tools whose auth headers are credential refs, never literals.
- Every tool in the five packages declares `effects`, so `@arnilo/prism-approval` (plan 154) governs them by mode with no per-package approval code.
- `@arnilo/prism-web-tools`, `@arnilo/prism-work`, `@arnilo/prism-coding-tools/{openapi,computer-use-linux}`, and the kernel `ExecutionPolicy` / `ExecutionAction` / `ExecutionDecision` / `assertExecutionAllowed` exports are gone. Their importers are migrated and the baselines regenerated.
- `examples/web-no-key.ts` runs under the execution gate and proves the Done criterion.

This plan implements roadmap **Phase 7 — Tool and context packages**, Part B. **Depends on plan 154.** Plan 154 Task 1 is the phase review for both parts, so this plan opens with an entry check instead of a second review.
