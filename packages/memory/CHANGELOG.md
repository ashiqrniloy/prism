# Changelog

## [Unreleased]

- **Working memory stops wasting passes (plan 217 Task 6).** A WM pass ends after a clean turn; calls past the per-turn limit are refused (the model re-sends them next turn) instead of failing the pass; after an attempt that records nothing or fails, WM waits for another `wm.observationTokens` of new records instead of re-running on every STM pass.
- **STM records a finished task as one outcome (plan 217 Task 6).** The default instruction folds a task finished or abandoned within a batch into one `outcome` event (old → new changes, how it was verified, setup facts found on the way) instead of overlapping request, action, change and result events; for unfinished work it records a result only when it adds to the records and an action only while its result is unknown; it leaves out tool-call ids and unrequested hashes, attaches chunks only when the description cannot hold the exact text, and rewrites the task state on every new request. The instruction stays about the same length (about 2,100 characters).
- **Memory workers' thinking levels reach the wire (plan 217 Task 6.1).** The worker loop maps `thinkingLevel` (`stm`, `wm`, `rehearsal`, the LTM extractor) against `await client.resolve?.()`, the provider's description of the model, instead of the bare `provider/model` ref, which carried no `compat`. Measured on Ollama Cloud: DeepSeek V4.1 Flash kept thinking at `stm.thinkingLevel: "none"` before this change.
- **Episode scope (plan 218 Task 1).** New `memory:scope { text } | { path } | { clear: true }` command, `scope.text` / `scope.maxBytes` config (default 32 KB, at most 48 KB; tuning) and `memory.system.setScope(session, text)` (resolves `{ hash, bytes }`; it no longer rejects with `not_available_yet`). The scope is redacted, stored in session state (forks carry it) and recorded as `memory.session.scope.set { hash, bytes, at }` (`SCOPE_SET`, a new stable export); text over the cap fails with `scope_too_large` naming the cap and is never truncated, and empty text is `scope_empty`. `{ path }` is resolved by the host through a `host.ui` `input` request (the package never opens a file); without an answer it is `scope_path_unresolved`. Only the WM (reflector) and Rehearsal (dropper) requests receive it, as an `<episode_scope>` block under a system rule that the block is data and changes no tool call; STM requests, the context block, compaction and long-term memory never do. With no scope the block says the episode is the session's current work and carries the task state. **Behaviour change:** WM and Rehearsal prompts open with that block and rule, and the `stm` component now declares `host-ui`. `memory:session:status` reports the scope's hash and size; `memory:session:model { reset: true }` keeps the scope. `MemorySystemErrorCode` gains `component_off`, `scope_too_large` and `scope_empty`.
- **An unknown tool name no longer fails a memory worker pass (plan 218 Task 1.1).** `runMemoryWorkerLoop` answers a call to a tool it was not given with an `unknown_tool` error result (`MEMORY_WORKER_UNKNOWN_TOOL`, a new export of `/core`) naming its tools, with the name redacted and truncated, for every worker (STM, WM, Rehearsal, the LTM extractor, the wiki curator). Valid calls in the same turn keep their effect; the refused call counts toward `maxToolCallsPerTurn` and `maxToolCalls`, and a turn with one is not clean. **Behaviour change:** the loop no longer throws `MemoryWorkerError("unknown_tool")`; byte limits, JSON depth, redaction and provider `error` events still fail the pass. Gate M-1 lost whole STM and WM passes to one garbled name (`record_rection`).
- **Working memory gives verdicts on named STM records, incrementally (plan 218 Task 2).** The whole-log reflector is gone: `workers/wm.ts` replaces `workers/reflector.ts`, its "rewrite the entire memory log" instruction and the flush's consume-everything-sent rule. A WM pass is sent at most `wm.batchTokens` (new, default 3,000; tuning) of the oldest STM surface records, with the scope, the task state (now also when a scope is set), the active WM items and salience marks (`error` events, user corrections, `hook_denied` tool results, failed verifications in outcomes). Its tools are `keep { stmId, reason }` (a WM `event`), `summarize { stmIds, text, relevance, supersedes? }` (a `summary`), `derive { text, supportingIds, relevance, supersedes? }` (a `fact`; no verdict) and `discard { stmId, reason: finished | out-of-scope | superseded | duplicate }`; each answers `ok: false` with `unknown_id`, `already_processed`, `empty_text` or `citation_outside_active_set` when it stored nothing. A record gets at most one verdict; one without a verdict stays on the STM surface. Every processed record is tombstoned (`wm keep <item>`, `wm summarize <item>`, `wm discard <reason>`) and stays recallable; in the same chunk-store transaction the new WM items add `wm` referrers for the chunks they cite and the tombstoned records' `stm` referrers are removed, so a cited chunk survives and an uncited one is deleted. A pass supersedes only the WM items it names. The pass runs when the STM surface reaches `wm.triggerTokens` (new, default 10,000; replaces `wm.observationTokens`, default 20,000, which now fails config with a pointer to `wm.triggerTokens`) or when a boundary marker is new since the last WM attempt; the empty-attempt backoff is kept. `memory.system.rehearse(session, { only: "wm" })` runs one pass now and resolves `{ items, processed }` (other calls still reject with `not_available_yet`). **Breaking (experimental):** `MemoryReflection`, `REFLECTIONS_RECORDED`, `ReflectionsRecordedData` and `activeReflections` are replaced by `MemoryWmItem` (`{ id, kind: event | summary | fact, text, relevance, citedIds, chunkRefs?, supersedes?, reason?, observedFrom?, observedTo?, tokenCount }`), `MemoryWmItemKind`, `WM_RECORDED` (`memory.session.wm.recorded`: `{ items, supersededItemIds?, processedIds?, boundaries }`), `WmRecordedData` and `activeWmItems`, with no alias; the ledger's `reflections`, `consumedObservationIds`, `supersededReflectionIds` and `latestReflectionCoverageId` become `wmItems`, `supersededWmItemIds` and `wmBoundariesSeen`; `FoldedMemoryDetails` is version 2 with `wmItems`. Folding a retired `memory.session.reflections.recorded` record or a version 1 folded payload throws `MemorySessionLedgerError`. The context block's `## Reflections` section is `## Working memory` (`- [id] (relevance) kind: text [chunk]`); `recall` finds WM items (`kind: "wm_item"`, cited records, chunks, source entries) and drops the `reflected` state; `memory:session:status`, `memory:session:view` and the `memory.session.status` event report `wmItems` instead of `reflections`; the worker kind `reflector` is `wm`. Long-term memory reads WM items where it read reflections (gather's `reflection` source, `remember({ reflectionId })`, supersession retirement) until plan 219 retires those paths.
- **Working memory compresses toward a target as pressure, with code-enforced protections (plan 218 Task 3).** New `wm.targetRatio` (default 0.2, 0.01 to 1; tuning) and `wm.policy` (`"model"` default, or `"deterministic"`; contract). The WM request states the target (`targetRatio` × the batch's tokens) after relevance, lists salient records under "Keep first" (corrections, denials, errors, failed verifications) and marks protected records. `session/protections.ts` (`protectedRecords`, `isProtectedWmItem`, shared with plan 219's Rehearsal) protects task-state requests and decisions, records an active WM `fact` cites, unresolved `error` events, open questions, and records cited by an item marked `neededLater` (a new optional argument of `keep`, `summarize` and `derive`, and field of `MemoryWmItem`); `discard` refuses them with `{ ok: false, reason: "protected", protection }`. A batch whose protected records alone exceed the target records `budgetUnmet { protectedTokens, targetTokens }` on `wm.recorded` and the ledger; `memory:session:status` shows it, with `thresholds.wmTargetRatio` and `wmPolicy`. Every `wm.recorded` that processed records carries `compression { processedTokens, itemTokens, targetTokens }`. `wm.policy: "deterministic"` makes no model call: it keeps protected records, outcomes and salient records, summarises nothing, and discards the lowest-relevance oldest to the target (tombstone `wm discard budget`). New type exports `MemorySystemWmPolicy`, `WmBudgetUnmet`, `WmCompression`.
- **Working memory re-judges after a scope change, and compaction renders WM first (plan 218 Task 4).** The first model WM pass after a `memory.session.scope.set` with a new hash is also sent the records WM discarded earlier whose chunks still live in this session (newest first, up to the new `wm.rejudgeTokens`, default 8,000, `0` off; tuning); `keep` may bring one back as a WM event, any other verdict answers `already_processed`, and `wm.recorded` carries `rejudge { scopeHash?, offered, kept, chunkDropped }` (new type export `WmRejudge`). The compaction summary, the pinned block and `memory:session:view` share one render that lists WM items as facts, then summaries, then events, before the unprocessed STM surface and the task state; compaction still makes no model call and keeps `context.recentMessages` verbatim. A new session-tier case in `prefix-stability.test.ts` pins the prefix byte-identical across three WM passes between compactions (I7), and the plan 202 cache-stability pin is re-attested (`docs/_evidence/memory-bench/218/equivalence.json`, 54 requests identical).
- **Speaker attribution: what the user stated is never folded into what the assistant proposed (plan 218 Task 4.1).** STM events gain an optional `attribution: "user" | "assistant" | "tool" | "mixed"` derived from the stored roles of their cited entries (never from a model argument), and WM items an `attribution` derived from what they rest on (new type export `MemoryAttribution`). **Behaviour change:** serialized message lines in worker requests lead with the role (`[time] [id] user: …`, `assistant:`, `tool:`) instead of `message:`; the context block, compaction summary and `memory:session:view` render an assistant-only `request`, `statement` or `decision` as `assistant proposal:` and a `mixed` record as `kind (user + assistant):`, and WM items as `kind (assistant proposal):` / `kind (user + assistant):`. The STM instruction adds one rule (a fact, number, date or decision the user states is its own event citing the user's entry; an assistant plan or estimate is a proposal) and stays under 2,100 characters; the WM instruction asks a summary that merges both sides to say which side said what. Records written before this carry no attribution and render as before. Gate M-1 (LongMemEval `9aaed6a3`) showed STM keeping an assistant-calculated plan instead of the user's own expense.
