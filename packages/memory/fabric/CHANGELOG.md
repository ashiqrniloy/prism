# Changelog

## [Unreleased]

### Added

- Delivery-tier proof (plan 188.5 Task 4): `prefix-stability.test.ts` pins the prompt-cache claim — ten turns with no memory write send one identical prefix (directory, then core) and no tail block — and `examples/memory-lifecycle.ts` now demonstrates the pinned core, a path cue injected once per session after a matching `read`, and an approved `memory:share`. No API change.

- Team store (plan 188.5 Task 3): `createFabricTeam` opens `<project root>/<team.dir>` as a markdown store under the fixed tenant/resource `team` / `project`, indexes it at `<tools.root>/.team-index/<project id8>.sqlite`, and trust scans every note on load — a flagged note is rewritten as a `candidate` with its `flags` and counted by `census()`/`memory:status`. `team: false | { dir, write }` is off by default. The store is recalled through `CreateMemoryFabricOptions.readOnlyScopes` as scope `team` (prior 0.075; shadowing `path` > `project` > `team` > `agent` > `user`), so writes, capacity, and widening never reach it. `memory:share { id }` writes one verified project note into it only after a `host.ui` confirm showing the note and the target path (`generated.by: human`, `sources` naming the private note, a `shared-to-team` log line); `write: "off"`, a denial, an absent UI, or a non-verified note refuses with a typed reason. `memory.insert` refuses `scope: "team"`. New exports: `createFabricTeam`, `resolveFabricTeamOptions`, `MemoryFabricTeamConfig`, `ResolvedFabricTeamOptions`, `FabricTeam`, `FabricTeamCensus`, `FabricTeamShareInput`, `FabricTeamShareResult`, `FabricTeamShareReason`, `FabricTeamApproval`, `TEAM_TENANT`, `TEAM_RESOURCE`.

- Path cues (plan 188.5 Task 2): `createFabricCues` shows a path-scoped note once per session, in the tail after the topic-injected block, when a file tool touches a matching file — `- [id] path <kind> (for <glob>) <text>`. `applies_to` globs are matched through an index bucketed by each glob's first literal segment, built from a bounded `scanMetadata` pass cached on the directory's write counter, then one bounded `get` for the matched text; no model call, and a turn with no new path does no work. Verified notes win; a candidate is marked `(candidate)` and shows only where no verified note covers the path. The `cues` config (`false | { budgetTokens, maxPerTurn }`, default on; 300/1000 tokens, 2/5 notes per turn) bounds each turn; `cues: false` makes no query. Cross-source dedup drops a note already in the core, already injected by topic, already cued, or verbatim in a visible file read; cues join the shared citation tracker and their injected set is session state, so a restore never re-injects. New exports: `MemoryFabricCuesConfig`, `ResolvedFabricCuesOptions`.

- Pinned core (plan 188.5 Task 1): `createFabricCore` renders a `Core memory` prefix block after the directory — verified `preference`/`fact`/`procedure` notes by descending storage strength S, pinned first, one `[id] text` line each, user scope first. The `core` config (`false | { maxTokens, scopes }`, default on; 600/1000 tokens) splits the budget across scopes with unused budget flowing to the other; the block is cached on the directory's write counter and carries no timestamp. New exports: `createFabricCore`, `resolveFabricCoreOptions`, `HARD_CORE_TOKENS`, `DEFAULT_CORE_OPTIONS`, `MemoryFabricCoreConfig`, `ResolvedFabricCoreOptions`, `FabricCore`, `FabricCoreBlock`, `FabricCoreScope`, `FabricCoreScopeBinding`, `CreateFabricCoreOptions`. With the markdown store each scope's slice is written to `<scope>/core.md` through the store's new `writeDerivedFile`.

- `kinds: ["all"]` is shorthand for every note kind `MEMORY_NOTE_KINDS` lists, in `fabric.recall` and in the `memory.recall` tool; one parser (`parseRecallKinds`) serves both, `all` unions with named kinds, and an unknown name still fails closed. Recalling an archived episode or procedure no longer needs a hand-written kind list.

- Added the `memory:lifecycle` command and its pure core (`src/lifecycle/inspect.ts`): one line per note with storage strength S, retrieval strength R, the use log, and the archive and widening gates that refused it, filtered by `id`, `key`, `includeArchived` (default `false`), and `limit` (default 20). Verdicts come from `shouldArchive`/`storageStrength`/`retrievalStrength`, and the widening verdict is note-level — replication across projects stays `maintain()`'s decision. New exports: `inspectNote`, `describeNote`, `InspectNoteInput`, `LifecycleDecisionView`, `LifecycleNoteView`.

- Maintenance can widen across projects the host does not bind (plan 188.4 Further Action 2): `CreateMemoryFabricOptions` gained `openScope?: (input: MemoryFabricScopeOpenInput) => Memory | undefined | Promise<Memory | undefined>`, called once per unbound project resource the widening pass discovers via `store.listResources({ prefix: "projects/" })`. A resolved project is scanned with its text and tokens, can supply the wider note's text, and its copies archive with `widenedTo`; an unresolved one stays metadata-only evidence, as before. A resolver that throws or returns a `Memory` whose scope is not the requested one opens nothing. Archive and capacity are still per bound scope. Exported `MemoryFabricScopeOpenInput`.

### Changed

- `examples/memory-lifecycle.ts` (plan 188.4 Task 7): the readable, deterministic demonstration of the whole lifecycle — candidate → verified by use → wider scope, archive → archive search → revival, and capacity merge/eviction — asserting its expectations and printing counts only. No API change.

- Scope widening, narrowing, and `maintain()` (plan 188.4 Task 6): `fabric.maintain()` now finishes with cross-project widening (verified lessons in `lifecycle.widen.minProjects` projects become `agent` candidates, project copies archive with `widenedTo`), path→project widening across sibling subtrees, and narrowing of wider notes that `contradictionsToSupersede` projects contradict (`validTo` + `retired` + `superseded-by-contradiction`). `MemoryFabricMaintainOptions` gained `scope` (one resource; archive and capacity only, no widening), the `memory:maintain` command is new, and `consolidate()` maintains the session's project scope at the end of each pass. `MemoryNoteMetadata` gained `widenedTo`; `FabricLifecycle` gained `supersede`. The maintenance orchestration moved out of `create.ts` into `lifecycle/maintain.ts`; `lifecycle/widen.ts` holds the pure decisions. `retrievalStrength` now places an unused note's single use at its creation ordinal (`created`) instead of session 0, so a newly written note no longer looks as old as the clock. New exports: `crossProjectGroups`, `siblingGroups`, `narrowingCandidates`, `mergedKeywords`, `DEFAULT_WIDEN_CONFIG`, `MIN`/`MAX_WIDEN_*`, and the `Widen*`/`SiblingGroup` types.

- Capacity budgets and merging (plan 188.4 Task 5): `fabric.maintain()` enforces `lifecycle.capacity` by merging duplicates, then episode clusters (`lifecycle.merge.episodes`, one model call each, off by default), then evicting the lowest `S·exp(R)` notes. New exports: `lifecycle/capacity.ts` (`DEFAULT_CAPACITY`, `capacityForLevel`, `capacityUsage`, `overCapacity`, `evictionOrder`, `MAX_FABRIC_CAPACITY_NOTES`, `MAX_FABRIC_CAPACITY_TOKENS`, `CapacityLimits`, `CapacityNote`, `CapacityUsage`) and `lifecycle/merge.ts` (`duplicateGroups`, `mergedMetadata`, `episodeClusters`, `summarizeEpisodeCluster`, `DEFAULT_DUPLICATE_DICE`, `DEFAULT_EPISODE_MIN_CLUSTER`, `MIN_DUPLICATE_DICE`, `MAX_DUPLICATE_DICE`, `MAX_EPISODE_CLUSTER`, `MAX_EPISODE_SUMMARY_CHARS`, `EPISODE_MERGE_TOOL`, `EPISODE_MERGE_SYSTEM`, `DuplicateGroup`, `EpisodeCluster`, `EpisodeSummary`). `MemoryFabricMaintenanceReport` gained `episodesMerged` and `overBudget`; `MemoryNoteMetadata` gained `mergedInto`; `FabricLifecycle.archive` takes `mergedInto` and `auditVerb`, and `FabricLifecycle.mergeMetadata` is new; `CreateMemoryFabricOptions` gained `notify`.

- Archive, revival, and archive search (plan 188.4 Task 4): `lifecycle/archive.ts` adds `shouldArchive`, `DEFAULT_ARCHIVE_CONFIG`, and `lifecycle.archive.{retrievalBelow,storageBelow,graceSessions}`; `fabric.maintain()` archives past the rule; `FabricLifecycle.archive(id)`/`pin(id, pinned?)` and `MemoryFabric.pin` are new; `MemoryNoteMetadata` gained `pinned`, `created`, and `archivedFrom`; `MemoryFabricRecallOptions` gained `includeArchived` and `archiveSearch`; recalled archived hits are marked `[archived]` and revive on citation. Removed: `FabricLifecycle.archiveStale`, `isStaleCandidate`, `DEFAULT_PROMOTE_ARCHIVE_AFTER_DAYS`, `HARD_PROMOTE_ARCHIVE_AFTER_DAYS`, `MemoryFabricPromoteConfig.archiveAfterDays`, and `ScopedMemoryPolicyKnobs.decay` (`candidateArchiveDays`). `createScopedMemoryPolicy` accepts `clock` and `archive`.

- Two strengths and the ranking prior (plan 188.4 Task 3): `lifecycle/strength.ts` adds `storageStrength`, `retrievalStrength`, `strengthPrior`, and `noteImportance`. Recall adds `w_R·σ(R) + w_S·σ(S)` after fusion and the scope prior; a note's core `importance` is its normalised S. `lifecycle.decay`, `lifecycle.storageWeights`, and `lifecycle.recall` configure the model; the scope clock now also stamps `recordUses`. `scoreScopedHit` and `scoped.policy.decay.tauDays` are removed: the scoped read policy no longer multiplies calendar-time decay into a score.

- The scope clock and the lifecycle scan (plan 188.4 Task 2): the fabric ticks each active scope's clock once per session on the first `context.build`, keeps the counted resources in session state so a restore never double counts, and warns when the store has no `scopeCounter`. `MemoryFabric.maintain({ signal })` is the maintenance entry point; today it fixes the capability gate — a store without `scanMetadata` refuses with `MemoryValidationError("maintenance requires scanMetadata")` and recall and writes are unaffected. `CreateMemoryFabricOptions.vectorStore` passes the store behind `memory`.


- One note lifecycle (plan 188.4 Task 1): status, use events, helpful/harmful evidence, and reconsolidation moved to `src/lifecycle/{index,events,status,evidence}.ts`. A use is a citation of a shown id, logged once per session per note as `{ s, at }` (scope-session ordinal and wall time) and counted in `useSessions`; a candidate verifies at `lifecycle.verifyAfterSessions` (default 2) distinct sessions with no harmful evidence, or by an explicit confirmation. Outcome tags record `helpful`; a user correction citing a note records `harmful`, sets `reconsolidate: true`, and returns a verified note to `candidate`. `retrievals` counts returns and never affects status. `MemoryNote` exposes `useSessions`, `retrievals`, `helpful`, `harmful`, and the capped `uses` log; `MemoryFabric.recordUse` is now `recordUses(sessionKey, ids, { clock, verifyAfterSessions })`. Retired: `promote.verifyAfterUses`, `lastUseKey`, the scoped ledger's per-note lifecycle rows, `touchScopedLedger`, `runScopedPromotionPass`, and `policy.promotionPass()`. The ledger keeps pending approvals and write statistics only, reads an older file with its lifecycle rows ignored (reported once), `scopedMemoryHealth(memory, ledgerFile)` reads the unified lifecycle, and the scoped reader records no use on retrieval.

### Fixed

- Lifecycle defect fixes (plan 188.1 Task 11 — D4, D5, D13):
  - D4: Superseded reflections retire their promoted notes with supersedes semantics (`validTo` set, correction lineage preserved, and logged as `superseded-by-om`). Replacement reflections created in the same pass are linked via `supersedes`. Verified notes edited after promotion (carrying correction lineage) are not retired; they are preserved with `reconsolidate: true` and surfaced in `memory:status`.
  - D5: Verification by use, not retrieval: `memory.recall` drops unconditional `touch` and `recordUse`. Recalled and injected note IDs share a unified `FabricCitationTracker` (`createFabricCitationTracker`). Usage increments only when the assistant cites a note (`[id]`) in turn completions, keyed by distinct session ID. The recall tool output prompts: `"Cite [id] for notes you use."`.
  - D13: Archive separate from validity: `archiveStale` sets `status: "archived"` and `archivedAt`, never setting `validTo`. Active recall, injection, and directory walks exclude archived notes via a unified `isActiveNote` predicate in `lifecycle.ts`. Historical time-scoped recall (`asOf` prior to `archivedAt`) sees archived, non-superseded notes as valid.

### Added

- Session consolidation, step 5 — triggers, cursor, command and status (plan 188.3 Task 5): the pass is wired to three triggers — `turn.completed` after `promote.minTurnsBetween` turns when OM recorded a new reflection, supersession or task-state decision after the cursor; `memory:consolidate`; and `session.opened` with `restored: true` (one catch-up) — with no timers and one pass per session at a time (a trigger during a running pass is dropped, not queued). The cursor advances only after every write succeeds, so a failed pass fails only its background task and retries on the next trigger. `fabric.consolidate(session, { signal, cursor })` is the host API (call it, or the command, before `session.close()`), `memory:status` now reports the last pass's counts and rejections by reason (`score`, `ephemeral`, `derivable`, `trust`, `secret`), and `promote` is reshaped to `false | { model, minScore, weights, maxCandidates, minTurnsBetween, derivableFrom, verifyAfterUses, archiveAfterDays }`, default `false` (no model call). Superseded reflections are handled by the pass, and a `reconsolidate` note is shown to the extractor as an existing note, rewritten in place by key/kind/scope, or retired when the extractor returns nothing for it.

- Session consolidation, step 4 — the write path (plan 188.3 Task 4): accepted notes go through the same `remember` an agent write uses, each stored with `status: candidate`, `generated: { by: "promotion", at, session }`, `sourceEntryIds`, and a `promotion: { score, signals, pass }` stamp. A contradiction of a wider-scope note is written as an exception in the narrower scope with the same `key` and `overrides` naming the wider note, so plan 188.2's key shadowing hides the wider note in that project only; the wider note records the project id in `contradictedIn` (deduplicated, ids only). Same-scope contradictions keep both notes linked `contradicts` and route to the decider's `SUPERSEDE` when configured. Reconsolidating notes are rewritten in place with the same id and correction lineage, or retired (`validTo`) when the extractor returns nothing for their key; a verified note is never demoted, and a flagged or archived one is never rewritten. New `overrides`, `contradictedIn`, and `promotion` note fields are parsed fail-closed. Per-reflection promotion is removed: `runFabricPromotion`, `promote.observational`, and the per-turn reflection trigger are gone, and `promote` now only configures the candidate lifecycle.

- Session consolidation, step 3 — scoring and the promotion gate (plan 188.3 Task 3): `scorePromotion(note, context)` returns `{ score, signals, accepted, reason }` from a transparent linear score — `explicit + correction + outcome·0.5 + recurrence·0.5 + generality·0.5 − ephemerality − derivability − duplicate·0.5` — with weights as exported data (`DEFAULT_PROMOTION_WEIGHTS`) and a default `minScore` of 0.5, provisional until plan 188.6 calibrates them. `explicit` and `correction` are cross-checked against the evidence's gathered candidate sources; `recurrence` is `log2(1 + distinct sessions)` normalised to 1 at four sessions; `ephemerality` rises to 1 for line references, temp paths, commit hashes, branch names and outlived dates; `derivability` covers the extractor flag and ≥ 0.9 lexical coverage by a `derivableFrom` file; `duplicate` is the highest Dice with an active note of the same kind in the target scope. Rejections carry one reason (`ephemeral`, `derivable`, `score`); an explicit user statement is never rejected for score. `loadDerivableSources(root, files)` reads those files once per pass through the fabric file jail (inside the root, 64 KiB cap) and reports `../`, absolute and symlink escapes as skipped notes instead of trusting them. No model call.

- Session consolidation, step 2 — the extractor (plan 188.3 Task 2): `extractConsolidationNotes({ client, candidates, segments, recallExisting, limits, redactor, secrets })` makes exactly one model call per pass through the shared worker loop, with one schema-declared tool, `record_notes`. The schema in `consolidation/prompts.ts` is the single source for the tool definition and for parsing, so an answer can only cite the candidates (`c1`, `c2`, ...) and existing-note ids it was shown. It returns atomic, typed notes — `fact`, `procedure`, `preference`, `episode` — with a proposed scope, keys and aliases, evidence ids, generality and ephemerality, and contradictions; `agent` scope is downgraded to `project`, and an episode is one per task segment at 280 characters or fewer. It fails closed (`ConsolidationExtractionError`, nothing written, cursor kept, one warning, retried on the next trigger) on a malformed answer, an unknown kind or scope, an unshown evidence or `contradicts` id, too many notes or an oversize item; an aborted call aborts the pass. The trust scan and the secret redactor drop individual notes and count them as `rejected.trust`/`rejected.secret`. Input is bounded by `workerLimits` before it is sent, and the default package load resolves no model client.

- Session consolidation, step 1 — candidate gathering (plan 188.3 Task 1): `gatherConsolidationCandidates(entries, { cursor, maxCandidates, maxTextChars, patterns, redact })` is a pure, bounded function over `session.entries()` that makes no model or store call. It gathers reflections no later record superseded, `om.task_state.recorded` decisions, `high`/`critical` observations, explicit user statements (matched sentence only), corrections (carrying the corrected assistant entry and the note ids cited in that turn), and tags candidates whose evidence shares a run with a successful test/commit tool result or an approval grant. Candidates are priority-ordered (explicit, correction, decision, observation, reflection), capped by `maxCandidates` (default 48) and per-candidate text, and idempotent for the same cursor. `CONSOLIDATION_PATTERNS` exports the default English pattern sets. Assistant text is never an explicit candidate and tool output is never candidate text (MINJA).

- Fabric OKF export and import for every store: `exportMemoryOkf(memory, { dir, stores })` writes the thread's notes, working memory, tombstones and holds, `index.md`, and `log.md` in the markdown layout (no embeddings), and `importMemoryOkf(memory, { dir, stores, mode })` reads a bundle into any store (SQLite, Postgres, in-memory, markdown). Imports stamp `generated.by: import`, scan every note and quarantine hits as candidates, re-embed only when an embedder is passed, and never clear or overwrite a target's legal hold. New `memory:export { dir }` and `memory:import { dir, mode }` commands resolve `dir` inside `tools.root` (plan 188.1 Task 7).

- Provenance and poisoning defenses (plan 188.1 Task 6): every durable write stamps `generated: { by, at }` (`agent` with the session id, `promotion` with the reflection and evidence ids, `human` for an external edit found by reconcile, `import`, or `host`). The markdown store's `log.md` records the actor on each line. Reconcile runs `scanScopedMemoryContent` once per externally changed file: a hit sets `status: candidate` with `flags: [<class>]`, rewrites the note, and logs `flagged`. Flagged notes are never injected passively and `memory.recall` marks them `[flagged: <class>]`; `memory.replace` or a clean human edit clears the flag. Injected fabric blocks carry the `untrusted`/`inert`/`injectionCapable` envelope. The scan is heuristic — review `log.md` and `git diff` (MINJA).

- The store defaults to markdown when `tools.root` is set: `store: "markdown" | { markdown: { dir } }` (default `notes`) writes canonical OKF note files with a derived `.index.sqlite` under the root, browsable with `memory.view`/`memory.read` and editable in place. `memory.replace { id }` rewrites the note file (a `corrected` invalidation no longer archives it), the file reconcile and directory walk skip `notes/**` as user files (the directory names `notes/index.md`), and the new `memory:reindex` command rebuilds the derived index and reports `indexed`/`removed`/`malformed` (`{ full: true }` re-reads every file). `{ sqlite }` and `{ postgres }` stay available but need `memory:export` to be inspectable.

- The memory family's cross-package integration suites (plan 158 Task 6): with the `@arnilo/prism-memory` workspace deleted, its remaining `__tests__` tree moved here — lineage, deletion propagation, grant-change source re-pointing, host wiring, eval revocation, RAG ACL, and the three Postgres integration suites. `@arnilo/prism-memory-rag` and `@arnilo/prism-memory-wiki` are development-only dependencies, `test:postgres` runs the Postgres legs, and `no_workspace_imports_prism_memory_family` guards that only frozen records name the retired family.
- `@arnilo/prism-memory-fabric` (plan 158 Task 4): the 0.12 memory fabric (typed notes,
  consolidation, the opt-in linker/evolution workers, working memory, the `createMemory` engine,
  the memory conformance harness) and the scoped policy layer moved out of
  `@arnilo/prism-memory/{fabric,scoped}` into their own package, plus the `memory.view`,
  `memory.read`, `memory.insert`, `memory.recall`, and `memory.forget` tools, a `context.build`
  block, and per-session enablement.
- Semantic memory consumes the `embeddings` service another package provides
  (`@arnilo/prism-memory-rag`); without it the package registers working memory only and notes why.

### Removed

- The `./fabric` and `./scoped` subpaths and the `createMemory` / `createMemoryWorkingStore` /
  `runMemoryConformance` exports of `@arnilo/prism-memory`; their importers now use
  `@arnilo/prism-memory-fabric`.
- The 0.12 `createMemoryFabric({...}).attach(session)` gate. Session scoping is the kernel's
  per-session state (`prism.state.session`), toggled by the `memory` command.
