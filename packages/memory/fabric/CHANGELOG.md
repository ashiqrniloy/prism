# Changelog

## [Unreleased]

- Source seam for the wiki (plan 207 Task 8): the `memory.fabric` port gains `sourceRoot()` (the fabric's `tools.root`, or `undefined`) and `indexSource({ path, text, contentHash, keywords })`, which runs the trust scan and then the ordinary write path for a `kind: "file"` note in the `project` scope: deterministic subject binding, dirty marking, no model call. A text the scan flags returns `{ indexed: false, refused }` and writes nothing; a fabric with no `tools.root` throws. `OntologyNoteView` carries `path` for `file` notes, and `OntologySourceInput` and `OntologySourceResult` are exported. The startup reconcile skips an ingested source's immutable original (`sources/<id>/source.<ext>`), which may be binary and would duplicate its `extract.md`. Additive; without the wiki package nothing changes.

- Human curation of concepts and the team ontology (plan 207 Task 7): a person's edit to a concept file is reviewed before it is indexed, in the private store and the checked-in team store alike, with no model call. A body that breaks the item grammar is rejected: the last valid version stays indexed, the file is left as written, and `log.md` gets one `invalid-concept` line (the writer is `human`). A claim whose text or citations changed, and a new claim, is marked `[c1 human]` in the file (a new part of the body grammar: `ConceptItem.human`); a marked or uncited claim is read-only to every writer but a person, and the port refuses `update_claim`, `retire_claim` and `merge_claims` on it with `claim_human`. `sources` and `title` are re-derived from the body, the stale mark of a changed claim is cleared, the concept gets the dirty reason `edited`, and `generated` becomes `human`. The trust scan runs on the title, aliases and body: a hit quarantines the concept as a `candidate` with `flags`, and a clean edit lifts it. `memory:reindex` invalidates the concept index. With `team` on, the team concepts are a read-only scope of the `memory.fabric` port (`scopes()` lists `team`; `applyConceptEdits` and `bind` on it fail with `MemoryScopeError`). The ontology `OntologyScope` may name its own `store`. Additive; with no concept file edited nothing changes.

- Curator port surface (plan 207 Task 6): the `memory.fabric` port gains what the wiki's concept pass needs. `pending` takes `subject`, `unbound` and `coRead` filters, evaluated in the same metadata scan; a note view carries `keywords`, `links`, `coRead`, `generatedBy` and, for a concept, `stale`; `settle(scope, subject)` clears a subject's `evidence` dirty reason when the curator had nothing to add; `screen(text)` names the trust class the fabric would refuse, so one offending edit can be dropped. All additive; nothing changes without the wiki package.

- Concepts first, then drill down (plan 207 Task 4): `memory.recall` is the one retrieval surface for the ontology tier. `concept` joins the default recall kinds and `kinds: ["all"]`, and a concept hit gets the tuning-tier kind prior `ontology.conceptPrior` (default 0.1, in [0, 0.5]) after fusion and the scope prior, so it outranks its own evidence but not a better-matching note. The recall tool renders a concept as a header, its current claims with the ids they cite (`ontology.maxClaimsRendered`, default 8, in [1, 32], chosen by term overlap) and a `drill down: memory.read { ids: [...] }` line; a stale claim, a claim with an unreadable citation and everything under a flagged concept are not rendered, and an uncovered pattern still returns as a plain note in the same call. `memory.read { id }` returns a whole concept with claim ids and `(stale)` / `(uncited, human)` labels; reading a note lets the model cite it. Passive delivery is a pointer only: at most one `- [id] concept <subject> — memory.read <id>` line per turn, for the top fused hit when a name is in the turn or a touched path is in its `appliesTo`; a path cue shows the same pointer, never claims, and a concept never enters the pinned core. `memory:share` accepts a verified concept (current claims only; the cited private notes are not copied; one per subject; a private concept shadows a team concept by subject). An answering turn that cites two or more received notes records a `coRead` event (`{ s, t, with }`, ids and indexes only, last 16 per note) in the existing lifecycle write, and a recorded use refreshes the concept's index row so the directory order follows use. `memory.recall` with `kinds: ["concept"]` is refused (`concept_requires_ontology`) only when `semantic` is off. New config: `ontology.conceptPrior`, `ontology.maxClaimsRendered`. New note field: `coRead`. No model call, no kernel change; with no concept notes every result is byte-identical.

- Ontology index and schema-assisted subject binding (plan 207 Task 3): a new T1 note is bound to the one subject it names when it is written. The scope's concept index feeds a token map built with the lexical index's own normalizer; exactly one subject with at least `ontology.bindThreshold` matched name tokens (default 2, tuning, in [1, 8]) or one whole multi-token alias binds the note, otherwise it stays unbound. No model call, never across scopes, and a note whose index cannot load is stored unbound. Binding marks the concept `dirty: ["evidence"]`. The consolidation extractor's per-call prompt lists the scope's subjects (≤ 64 per scope) and `record_notes` gains an optional free-string `subject` (a shown slug or `new`; anything else is dropped); its cached system text and tool bytes are identical with and without an ontology. A concept gets a directory line, `project concepts: 12; subjects: a, b, c (+9)`, inside the existing budget and pinned for the session epoch. `CreateMemoryFabricOptions.subjects` takes `createFabricOntology(...).subjects`; the package wires it. Fixes a Task 2 gap: a reconsolidating rewrite no longer drops a note's `subject`. With no concepts nothing changes.

- Ontology tier, store side (plan 207 Task 2): a new opt-in `concept` note kind (one per subject: itemized claims, each citing T1 note ids with OKF footnotes, closed relation set `part-of`/`instance-of`/`uses`/`related`) and an additive `subject` field on every kind. The deletion cascade is deterministic and model-free: forgetting, deleting, revoking or holding a note removes every claim that cites it (an empty concept is archived), and a correction, supersession, archive, downgrade or flag marks the citing claims stale. It hangs off a new id-carrying retraction event fired from invalidation, `patchEntry`, retention, import and supersede. The `memory.fabric` service (`FabricOntologyPort`) is provided whenever `semantic` is on: `scopes`, `subjects`, `pending`, `read`, `applyConceptEdits`, `bind`, `dirty`. The memory tools refuse to write, edit or delete a concept (`concept_requires_ontology`); the directory, the core and `memory:maintain` ignore them. New actor `consolidation` for `generated.by`. The OKF file gains `subject`, `concept_type` and `aliases` frontmatter and `concepts/`. Nothing is on by default and no default result changes; plan 208 measures it, plan 210 decides its default.

- OM role measurement (plan 202 Task 16): the ordinary `promote` pass is the T0 path; `promote.observational` stays retired. Seven offline lifecycle seeds measured fabric alone at 0.375 → 0.393 and OM+fabric at 0.732 → 0.732 with promotion, with 0.125/0.25 promoted notes per session and zero later-use verification. The reference host keeps promotion off. A six-run one-question smoke on two models completed all arms without worker errors; the benchmark now records non-budget OM worker failures instead of aborting the arm. Live worker cost and evidence are under `docs/_evidence/memory-bench/202/observational/`.

- Growth and lifetime archive (plan 202 Task 15): add `lifecycle.exchangeCapacity: { hotTokens }` (default 200,000), separate from the per-scope note/token budgets. Exchanges over the hot tier are demoted with `auditVerb: "demoted"`; text survives in the searchable archive and remains retrievable. `fabric.maintain()` now excludes exchanges from the regular capacity pass, so a lifetime transcript cannot evict learned facts or grow an unbounded hot set. New growth and exchange-scale harnesses: 12-month LongMemEval-M stream passes the month-12/month-1 criterion, and 100k-exchange p95 lexical recall is 1.06 ms on SQLite and 4.15 ms on Postgres. Refreshed markdown scale evidence. SQLite generation fallback is cached across read-only queries and cleared on writes; lexical coverage uses stored index terms.

### Added

- Coding decisions and the coding preset (plan 202 Task 11): a new additive `decision` note kind carries `rationale` and `decisionStatus` (`proposed`/`active`/`superseded`) with the existing `scope`, `appliesTo`, `supersedes` and `sourceEntryIds`. The preset makes no write-path generative call and needs no embeddings service; the measured coding-lifecycle target remains with Plan 210 Task 9. `memory:status` reports `preset: "coding"` / `presetRevision: 1`; `CODING_PRESET_REVISION` and `MemoryDecisionStatus` are exported. The reference host accepts `memory: "coding"`.

- Adaptive passive delivery (plan 202 Task 10): the package now tracks per-session user turns that ask for a selection, list, count, comparison, or time ordering. After two such turns with no `memory.*` call, passive delivery switches from Task 8 pointer cards to full notes inside the same `inject.budgetTokens` and confidence floor; any `memory.*` tool call resets the counter and the next turn uses pointers again. State lives in package session state (`fabric.delivery`), is never shared across sessions or principals, and makes no model, embedding, or query call. `memory:status` reports `delivery: "pointers" | "excerpts"` and `reason`. No kernel, store, config, preset, or model-call change; the start mode stays pointers because the model catalog has no tool-reliability field.

- Evidence-shaped recall output (plan 202 Task 9): `memory.recall` now starts with a two-line grouped summary — total matches, distinct sessions, date span, per-session counts and dates, how many are shown, how many more are not, and the next page (`page`, zero-based, with `topK` as page size over a 32-hit window). The summary is capped under 200 rendered tokens and counted inside the existing `budget`; the tool trims a trailing hit if needed. Empty and weak-only results are explicit abstentions (`no matching memory for: <terms>; scopes: <active levels>`) with no hits, and the tool description tells the agent to list instances and ids before counting or totalling. Context blocks already carry the citation sentence. No model call, no kernel or store change.

- Precision-first passive delivery (plan 202 Task 8): two tuning-tier `inject` floors now gate the passive block. `minScore` (default `0.2`) drops low-confidence hits; when every hit is dropped the block carries only the `Showing 0 of M matching notes.` cue and the directory. Between `minScore` and `fullTextScore` (default `0.35`), an exchange renders as a pointer card — id, event date, the user's first 120 characters, and matched query terms — never its assistant reply; at or above `fullTextScore` it renders as before. The diagnostic mirror (`scripts/memory-bench/retrieval-diagnostics.mjs`) applies the same floors and keeps exact rendered-text parity. No kernel, store, model-call or preset change.

- Read-time current state (plan 202 Task 7): `memory.recall` now groups same-subject hits newest-first — keyed notes by `key`, exchanges by overlapping Task 5 subject keywords, plus explicit `supersedes` edges. The opt-in `state: {}` config adds one StateMem-style model call per explicit `memory.recall` over the grouped, budget-selected hits, returning a compact current-state table with cited ids in the tool text and `value.state`. `state` is absent from the conversational preset, passive injection never calls it, its input is capped at 2,000 estimated tokens, and a failed or uncited wrapper leaves normal recall unchanged. New exports: `MemoryFabricStateConfig`, `ResolvedStateConfig`.

### Added

- Session consolidation, step 5 — triggers, cursor, command and status (plan 188.3 Task 5): the pass is wired to three triggers — `turn.completed` after `promote.minTurnsBetween` turns when OM recorded a new reflection, supersession or task-state decision after the cursor; `memory:consolidate`; and `session.opened` with `restored: true` (one catch-up) — with no timers and one pass per session at a time (a trigger during a running pass is dropped, not queued). The cursor advances only after every write succeeds, so a failed pass fails only its background task and retries on the next trigger. `fabric.consolidate(session, { signal, cursor })` is the host API (call it, or the command, before `session.close()`), `memory:status` now reports the last pass's counts and rejections by reason (`score`, `ephemeral`, `derivable`, `trust`, `secret`), and `promote` is reshaped to `false | { model, minScore, weights, maxCandidates, minTurnsBetween, derivableFrom, verifyAfterUses, archiveAfterDays }`, default `false` (no model call). Superseded reflections are handled by the pass, and a `reconsolidate` note is shown to the extractor as an existing note, rewritten in place by key/kind/scope, or retired when the extractor returns nothing for it.

- Session consolidation, step 4 — the write path (plan 188.3 Task 4): accepted notes go through the same `remember` an agent write uses, each stored with `status: candidate`, `generated: { by: "promotion", at, session }`, `sourceEntryIds`, and a `promotion: { score, signals, pass }` stamp. A contradiction of a wider-scope note is written as an exception in the narrower scope with the same `key` and `overrides` naming the wider note, so plan 188.2's key shadowing hides the wider note in that project only; the wider note records the project id in `contradictedIn` (deduplicated, ids only). Same-scope contradictions keep both notes linked `contradicts` and route to the decider's `SUPERSEDE` when configured. Reconsolidating notes are rewritten in place with the same id and correction lineage, or retired (`validTo`) when the extractor returns nothing for their key; a verified note is never demoted, and a flagged or archived one is never rewritten. New `overrides`, `contradictedIn`, and `promotion` note fields are parsed fail-closed. Per-reflection promotion is removed: `runFabricPromotion`, `promote.observational`, and the per-turn reflection trigger are gone, and `promote` now only configures the candidate lifecycle.

- Session consolidation, step 3 — scoring and the promotion gate (plan 188.3 Task 3): `scorePromotion(note, context)` returns `{ score, signals, accepted, reason }` from a transparent linear score — `explicit + correction + outcome·0.5 + recurrence·0.5 + generality·0.5 − ephemerality − derivability − duplicate·0.5` — with weights as exported data (`DEFAULT_PROMOTION_WEIGHTS`) and a default `minScore` of 0.5, provisional until plan 188.6 calibrates them. `explicit` and `correction` are cross-checked against the evidence's gathered candidate sources; `recurrence` is `log2(1 + distinct sessions)` normalised to 1 at four sessions; `ephemerality` rises to 1 for line references, temp paths, commit hashes, branch names and outlived dates; `derivability` covers the extractor flag and ≥ 0.9 lexical coverage by a `derivableFrom` file; `duplicate` is the highest Dice with an active note of the same kind in the target scope. Rejections carry one reason (`ephemeral`, `derivable`, `score`); an explicit user statement is never rejected for score. `loadDerivableSources(root, files)` reads those files once per pass through the fabric file jail (inside the root, 64 KiB cap) and reports `../`, absolute and symlink escapes as skipped notes instead of trusting them. No model call.

- Session consolidation, step 2 — the extractor (plan 188.3 Task 2): `extractConsolidationNotes({ client, candidates, segments, recallExisting, limits, redactor, secrets })` makes exactly one model call per pass through the shared worker loop, with one schema-declared tool, `record_notes`. The schema in `consolidation/prompts.ts` is the single source for the tool definition and for parsing, so an answer can only cite the candidates (`c1`, `c2`, ...) and existing-note ids it was shown. It returns atomic, typed notes — `fact`, `procedure`, `preference`, `episode` — with a proposed scope, keys and aliases, evidence ids, generality and ephemerality, and contradictions; `agent` scope is downgraded to `project`, and an episode is one per task segment at 280 characters or fewer. It fails closed (`ConsolidationExtractionError`, nothing written, cursor kept, one warning, retried on the next trigger) on a malformed answer, an unknown kind or scope, an unshown evidence or `contradicts` id, too many notes or an oversize item; an aborted call aborts the pass. The trust scan and the secret redactor drop individual notes and count them as `rejected.trust`/`rejected.secret`. Input is bounded by `workerLimits` before it is sent, and the default package load resolves no model client.

- Session consolidation, step 1 — candidate gathering (plan 188.3 Task 1): `gatherConsolidationCandidates(entries, { cursor, maxCandidates, maxTextChars, patterns, redact })` is a pure, bounded function over `session.entries()` that makes no model or store call. It gathers reflections no later record superseded, `om.task_state.recorded` decisions, `high`/`critical` observations, explicit user statements (matched sentence only), corrections (carrying the corrected assistant entry and the note ids cited in that turn), and tags candidates whose evidence shares a run with a successful test/commit tool result or an approval grant. Candidates are priority-ordered (explicit, correction, decision, observation, reflection), capped by `maxCandidates` (default 48) and per-candidate text, and idempotent for the same cursor. `CONSOLIDATION_PATTERNS` exports the default English pattern sets. Assistant text is never an explicit candidate and tool output is never candidate text (MINJA).

- Fabric OKF export and import for every store: `exportMemoryOkf(memory, { dir, stores })` writes the thread's notes, working memory, tombstones and holds, `index.md`, and `log.md` in the markdown layout (no embeddings), and `importMemoryOkf(memory, { dir, stores, mode })` reads a bundle into any store (SQLite, Postgres, in-memory, markdown). Imports stamp `generated.by: import`, scan every note and quarantine hits as candidates, re-embed only when an embedder is passed, and never clear or overwrite a target's legal hold. New `memory:export { dir }` and `memory:import { dir, mode }` commands resolve `dir` inside `tools.root` (plan 188.1 Task 7).

- Provenance and poisoning defenses (plan 188.1 Task 6): every durable write stamps `generated: { by, at }` (`agent` with the session id, `promotion` with the reflection and evidence ids, `human` for an external edit found by reconcile, `import`, or `host`). The markdown store's `log.md` records the actor on each line. Reconcile runs `scanScopedMemoryContent` once per externally changed file: a hit sets `status: candidate` with `flags: [<class>]`, rewrites the note, and logs `flagged`. Flagged notes are never injected passively and `memory.recall` marks them `[flagged: <class>]`; `memory.replace` or a clean human edit clears the flag. Injected fabric blocks carry the `untrusted`/`inert`/`injectionCapable` envelope. The scan is heuristic — review `log.md` and `git diff` (MINJA).

- The store defaults to markdown when `tools.root` is set: `store: "markdown" | { markdown: { dir } }` (default `notes`) writes canonical OKF note files with a derived `.index.sqlite` under the root, browsable with `memory.view`/`memory.read` and editable in place. `memory.replace { id }` rewrites the note file (a `corrected` invalidation no longer archives it), the file reconcile and directory walk skip `notes/**` as user files (the directory names `notes/index.md`), and the new `memory:reindex` command rebuilds the derived index and reports `indexed`/`removed`/`malformed` (`{ full: true }` re-reads every file). `{ sqlite }` and `{ postgres }` stay available but need `memory:export` to be inspectable.

- The memory family's cross-package integration suites (plan 158 Task 6): with the `@arnilo/prism-memory` workspace deleted, its remaining `__tests__` tree moved here — lineage, deletion propagation, grant-change source re-pointing, host wiring, eval revocation, RAG ACL, and the three Postgres integration suites. `@arnilo/prism-memory-rag` and `@arnilo/prism-memory-wiki` are development-only dependencies, `test:postgres` runs the Postgres legs, and `no_workspace_imports_prism_memory_family` guards that only frozen records name the retired family.
- `@arnilo/prism-memory-fabric` (plan 158 Task 4): the 0.12 memory fabric (typed notes,
  consolidation, the opt-in linker/evolution workers, working memory, the `createMemory` engine,
  the memory conformance harness) and the scoped policy layer moved out of
  `@arnilo/prism-memory/{fabric,scoped}` into their own package, plus the `memory.view`,
  `memory.read`, `memory.insert`, `memory.recall`, and `memory.forget` tools, a `context.build`
  block, and per-session enablement.
- Semantic memory consumes the `embeddings` service another package provides
  (`@arnilo/prism-memory-rag`); without it the package registers working memory only and notes why.
