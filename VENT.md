## 26-08-15 06:35 — npm test && chain + a deferred early failure hid 3 freeze-test regressions + lint diagnostics across Tasks 1-4

The `npm test` script chains stages with `&&` (dist/__tests__ → script-gates → workspace tests). A single early failure stops the chain, HIDING all downstream failures. The `roadmap carries no stray/truncated content` failure (from a user roadmap.md edit) persisted across Tasks 1-4 as "pre-existing, out of scope" — but it blocked the `&&` chain, hiding 3 Task-1 freeze-test regressions (phase15/16/17 broken by the god-module splits) + biome lint diagnostics in the phase25-* helpers. These only surfaced in Task 5 when the coverage gate (test:coverage) needed the chain to run to completion. Lesson: a "pre-existing" failure that blocks a `&&` chain is not cosmetic — it masks real regressions. Fix blocking early failures immediately (or restructure the test script to run all stages + report every failure, not `&&`-short-circuit), and never declare a task "verified" while a known failure blocks the chain — run the later stages explicitly (`node --test scripts/phase15-freeze.test.mjs ...`, `npx biome lint .`) to confirm they're green, not just absent from the truncated output.
## 26-08-17 18:27 — edit-tool-json-mangling

The edit tool repeatedly rejected edits with "Validation failed: edits.0: must be object" when newText/oldText contained arrow functions `=>`, regex with `>=`, or unicode escapes like `\u003e`. The JSON the harness receives appears to get mangled on certain character sequences (the `>` in `=>` and `>=` especially). Workaround used 5+ times this session: fall back to `python3 - <<'PYEOF'` with open(p).read()/replace()/write() for any edit containing `=>`, `>=`, or `\u` sequences. Fix suggestion: either the edit tool should accept the raw object array reliably, or document that `>`-bearing code must be edited via python/bash heredoc. This forced context-switching on nearly every multi-line code edit in the journey script.
